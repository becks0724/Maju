# 운전자 무응답 확인(가칭) 베타 중계 서버

차 앱(Pleos) · 휴대폰 앱 · 워치 앱이 서로의 최신 상태와 지시를 주고받게 하는 베타용 중계 서버다. 차 앱은 푸시를 받을 수 없어서 모든 쪽이 2초마다 `sync` 를 보내고, 응답에 상대 상태와 대기 지시를 받아 간다. 규격은 `contracts/guardian/protocol.md` 를 따른다.

- 파이썬 3 표준 라이브러리만 쓴다. 설치할 패키지가 없다.
- **메모리에만 보관한다.** 디스크에 아무것도 쓰지 않고, 끄면 짝 · 상태 · 지시가 모두 사라진다.
- 접근 로그는 메서드 · 경로 · 상태 코드 · 처리 시간만 남긴다. 본문 · 토큰 · 위치 · 심박은 남기지 않는다(가이드라인 G2).
- 베타는 LAN 평문 HTTP 다. 같은 Wi-Fi 안에서만 쓰고, 실제 건강 · 위치 값 대신 테스트 모드 위주로 시험한다. 공개 운영은 HTTPS 서버로 따로 한다(사용자 결정).

## 실행

```bash
# 이 Mac 에서만(기본 127.0.0.1) — Pleos 에뮬레이터만 붙일 때
python3 server/guardian-relay/relay.py

# 같은 Wi-Fi 의 휴대폰 · 워치도 붙일 때
python3 server/guardian-relay/relay.py --bind 0.0.0.0 --port 8095

# 살아 있는지
curl -s http://127.0.0.1:8095/v1/health    # {"ok":true}
```

끌 때는 실행한 터미널에서 Ctrl+C 를 누른다. 백그라운드로 띄웠다면 확인한 PID 로만 끈다(`lsof -nP -iTCP:8095 -sTCP:LISTEN` 으로 PID 확인 → `kill <PID>`). `pkill -f` 는 쓰지 않는다.

## 접속 주소

| 기기 | 주소 | 비고 |
|---|---|---|
| Pleos 에뮬레이터(차 앱) | `http://10.0.2.2:8095` | 에뮬레이터 안에서 `10.0.2.2` 가 Mac 의 `127.0.0.1` 이다. 기본 바인딩으로 충분하다 |
| 휴대폰 · 워치(같은 Wi-Fi) | `http://<Mac LAN IP>:8095` | `--bind 0.0.0.0` 필요. Mac 주소는 `ipconfig getifaddr en0` |
| Pixel AVD(휴대폰 대신) | `http://10.0.2.2:8095` | 에뮬레이터라 차 앱과 같다 |

- 앱은 debug 빌드에서만, 설정한 주소만 평문 HTTP 를 허용한다(network security config). Mac LAN IP 는 빌드 설정값으로 넣는다(설계 §12).
- Mac 의 Wi-Fi 주소는 공유기가 바꿀 수 있다. 연결이 안 되면 주소부터 다시 확인한다.
- 휴대폰에서 브라우저로 `http://<Mac LAN IP>:8095/v1/health` 를 열어 `{"ok":true}` 가 나오면 네트워크는 된다.

## macOS 방화벽

- 「시스템 설정 → 네트워크 → 방화벽」이 켜져 있으면 처음 `--bind 0.0.0.0` 로 띄울 때 들어오는 네트워크 연결을 허용할지 묻는 창이 뜬다. 창에 나오는 앱 이름은 설치 방식에 따라 「Python」 · 「Python.app」 · 「python3」 처럼 다를 수 있다. **허용**을 누른다.
- 이미 거부했다면 「방화벽 → 옵션」에서 그 Python 항목을 「들어오는 연결 허용」으로 바꾼다.
- 공용 Wi-Fi(카페 등)에서는 `--bind 0.0.0.0` 로 띄우지 않는다. 같은 망의 누구나 접속할 수 있다.
- 회사 · 학교 Wi-Fi 는 기기끼리 통신을 막는 곳(클라이언트 격리)이 있다. 그때는 휴대폰 핫스폿에 Mac 을 붙인다.

## 직접 해 보기(curl)

```bash
B=http://127.0.0.1:8095
curl -s -X POST $B/v1/pair/start                           # {"pairCode":"123456","carToken":"...","expiresInSec":600}
curl -s -X POST $B/v1/pair/join -d '{"pairCode":"123456"}'  # {"phoneToken":"...","pairId":"..."}
curl -s -X POST $B/v1/pair/join -d '{"pairCode":"123456","role":"WATCH"}'  # {"watchToken":"...","pairId":"..."}
curl -s -X POST $B/v1/pair/code -d '{"token":"<carToken>"}'  # 워치 다시 붙이기 — 새 코드(끊긴 역할만 참여)
curl -s -X POST $B/v1/car/sync -d '{"token":"<carToken>","seq":1,"sentAt":0,"vehicle":{"speedKmh":0,"gear":"P"},"flow":null,"commands":[],"acks":[]}'
```

## 공개로 올릴 때

공개 인터넷에는 이 서버를 직접 열지 않는다. **TLS 를 끝내는 프록시(nginx · Caddy 등) 뒤 127.0.0.1 에서** 돌리고 `--trust-proxy` 를 준다. 호스팅 · 도메인 · 인증서는 사용자 몫이다.

```bash
python3 server/guardian-relay/relay.py --bind 127.0.0.1 --port 8095 --trust-proxy
```

프록시는 `X-Forwarded-For` 의 **맨 끝에 실제 접속 주소를 붙여야** 한다(nginx `proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;`, Caddy 는 기본). 중계는 그 마지막 값만 믿는다 — 앞 값은 클라이언트가 지어낼 수 있다. 프록시를 두 겹 이상 두면 바깥 프록시가 붙인 값이 끝에 오지 않으므로 안쪽 프록시에서 실제 주소를 다시 정해야 한다. `--trust-proxy` 없이는 헤더를 보지 않고 소켓 주소(프록시 뒤라면 모두 127.0.0.1)로 센다. **프록시 없이 열린 포트에 `--trust-proxy` 를 주면 누구나 주소를 지어내 제한을 피한다.**

프록시 쪽에서도 연결 · 본문 · 시간 제한(nginx `client_max_body_size 64k` · `client_header_timeout` · `limit_conn`)을 두면 중계 앞에서 한 번 더 거른다.

| 옵션 | 기본 | 뜻 |
|---|---|---|
| `--trust-proxy` | 끔 | `X-Forwarded-For` 마지막 값을 보낸 주소로 쓴다 |
| `--join-fail-per-addr` · `--join-fail-window-sec` · `--join-block-sec` | 10 · 600 · 600 | 주소마다 `pair/join` 실패가 창 안에서 문턱에 닿으면 그 주소의 `pair/join` 을 막는 시간 |
| `--code-fail-max` | 5 | 살아 있는 번호 하나에 걸린 실패 상한(닿으면 번호를 버림) |
| `--code-per-pair` · `--code-per-addr` · `--code-window-sec` | 10 · 20 · 600 | `pair/code` 횟수(짝마다 · 주소마다, 창 안) |
| `--start-per-addr` · `--start-window-sec` | 10 · 60 | `pair/start` 횟수(주소마다, 창 안) |
| `--max-pairs` | 64 | 살아 있는 짝 수(넘으면 503 `CAPACITY`) |
| `--pairs-per-addr` · `--pair-idle-sec` · `--joined-idle-sec` | 8 · 120 · 600 | 주소마다 살아 있는 짝 수. 닿으면 그 주소에서 세 역할(차 · 휴대폰 · 워치) 모두 sync 가 없는 짝 하나를 지우고(참여한 적 없는 짝 120초 · 참여한 적 있는 짝 600초), 없으면 429. 공개 운영 값은 아래 |
| `--join-fail-v6-prefix` | 48 | `pair/join` 실패를 셀 때 IPv6 를 묶는 넓이(그 밖의 제한은 /64) |
| `--max-keys` | 4096 | 계수기마다 기억하는 주소 · 짝 수(꽉 차면 막히지 않은 가장 오래된 키를 밀어냄) |
| `--max-conns` | 256 | 동시 연결 수(넘으면 응답 없이 닫음) |
| `--request-deadline-sec` | 20 | 요청 하나를 다 읽고 답하는 전체 시간(느린 요청 끊기) |

- 기본값은 같은 Wi-Fi 시연(기기 3대가 한 공유기 주소로 2초마다 sync · 다시 짝짓기 몇 번 · 번호 잘못 누르기 몇 번)을 막지 않는다(`test_limits.py` `DemoFlowTest`). adb 터널처럼 모든 기기가 한 주소이고 차 앱을 90초마다 재설치하며 매번 휴대폰 · 워치가 다시 참여해도 `pair/start` 가 막히지 않는다(기본 8자리, 옛 짝은 세 기기가 모두 떠난 뒤 10분이면 밀려남 — `PairsPerAddrTest.test_demo_car_reinstalls_on_one_address_default`). 그보다 잦게(10분 안에 8번 넘게) 재설치하면 차가 10초마다 다시 보내며 가장 오래된 옛 짝이 10분 조용해질 때까지 기다린다. 「휴대폰 연결 끊기」로 끝낸 짝은 바로 자리가 빈다.
- **공개 운영 값** — 기본 8 은 한 주소 시연용이다. 공개로 올릴 때는 `--pairs-per-addr 3` 정도를 권한다(주소 하나가 쥘 수 있는 자리를 줄임). 그 대신 통신사 공유 주소(CGNAT) 뒤 여러 차가 같은 주소로 보이면 쓰는 중인 짝이 3개인 주소의 4번째 차는 429 다. 8 로 두면 주소 하나가 전체 64자리 가운데 8자리를 쥘 수 있다. 실제 차량 망의 주소 모양을 보고 정한다.
- 제한에 걸리면 429 `RATE_LIMITED` 다. 401 은 내지 않으므로 앱의 짝이 지워지지 않는다. 규칙 전체는 계약 §3.1.1 · §7.
- 나이 · 만료(짝 24시간 · 번호 10분 · 지시 ttl · 제한 창)는 단조 시계로 잰다. 서버 시계가 NTP 로 바뀌어도 `ageMs` 가 음수가 되거나 짝이 갑자기 만료되지 않는다(계약 §2). 이 시계는 잠자기도 센다(Linux `CLOCK_BOOTTIME` · macOS `clock_gettime(CLOCK_MONOTONIC)`, C-4).
- 모든 응답 뒤 연결을 닫는다. `Content-Length` 는 숫자만, `Transfer-Encoding` · 본문 있는 health 는 400(D-3).
- 지시는 허용 표(`contracts/guardian/command-roles.json` 과 같은 `COMMAND_ROLES`) 안만 받는다. 지시 하나 8KB · ttl 120초 · 받는 쪽 중복 막기 기록 512(D-1 · D-3).
- 받는 쪽 큐는 256개 · 64KB 까지(넘으면 오래된 것부터 버림), 본문 중첩은 32 단계까지(sec-audit 3차).
- **공개 조건(sec-audit 3차)** — 중계의 주소별 동시 처리 상한은 머리를 읽은 뒤부터 세므로, 머리를 덜 보낸 느린 연결은 마감(기본 20초)까지 연결 자리를 쥔다. 프록시 뒤에서는 소켓 상대가 모두 루프백이라 중계에서 더 줄이기 어렵다 — 앞단 프록시의 머리 읽기 시간과 주소별 연결 수 제한을 함께 둔다.
- 새 실행 인자(2026-11-14) — `--sync-per-token`(기본 30) · `--sync-window-sec`(2) · `--concurrent-per-addr`(16). `--trust-proxy` 는 루프백 `--bind` 와만 시작한다. 60초마다 주소 · 토큰 없는 계수 줄(`stats …`)을 남긴다(D-4).
- 보낸 쪽 주소는 메모리의 계수기에만 있고 로그에 남지 않는다.

**한계(공개 전에 알아 둘 것)**

- 6자리 번호(100만 가지)는 주소를 많이 가진 공격자(봇넷 · IPv4 여러 개 · IPv6 /48 여러 개)를 완전히 막지 못한다. 키 하나(IPv4 주소 하나 · IPv6 /48 하나)로는 10분에 10번이라, 살아 있는 번호가 64개 꽉 찬 최악에도 하루 약 1,440번 · 맞힐 확률 약 9% 이고, 키 수만큼 늘어난다. 근본 대책은 번호를 길게 하거나 차 화면 확인을 더하는 것인데 앱이 바뀌어야 한다(앱 동결).
- `pair/join` 실패를 IPv6 /48 로 묶으므로 같은 /48 을 나눠 쓰는 다른 가입자(통신사가 /56 씩 나눠 줄 때 최대 256곳)가 함께 막힐 수 있다. 정상 사용자는 실패가 드물어 받아들였다. 반대로 IPv6 /48 을 여럿 가진 공격자에게는 그만큼 키가 늘어난다.
- 계수기를 밀어내기로 바꿔서, 키를 4,096개 넘게 가진 공격자는 새 키로 계수기를 계속 흔들어 **막히기 전의 제 실패 기록(10번 미만)** 을 밀어낼 수 있다. 막힌 키는 밀려나지 않지만, 막히기 전에 기록을 지워 문턱에 닿지 않게 할 수 있다. 이 공격에는 IPv4 주소 · IPv6 /48 이 4,096개 넘게 필요하다. 모든 키가 막혀 꽉 찬 뒤에는 새 키를 세지 못한다(막지도 않는다).
- 짝 자리 — 주소(IPv4 하나 · IPv6 /64 하나)마다 살아 있는 짝이 기본 8개(공개 권장 3개)라, 전체 64자리를 24시간 붙잡으려면 주소 8개(3 이면 22개) 이상이 필요하고 짝마다 세 역할 가운데 하나로 sync 를 계속 보내야 한다. IPv6 /64 를 여럿 가진 공격자(/48 하나면 /64 가 65,536개)는 이 조건을 쉽게 채우므로 전체 상한 64 를 503 으로 막을 수 있다. 주소별 짝 상한을 /48 로 넓히면 같은 /48 의 다른 가입자 차가 막히므로 넓히지 않았다.
- 통신사 공유 주소(CGNAT) 뒤의 차 여러 대는 공인 IPv4 하나를 나눠 쓴다. 쓰는 중인 짝이 상한만큼 그 주소에 있으면 같은 주소의 다음 차는 429 다. 차가 이동통신으로 붙으면 이 일이 흔할 수 있다.
- 같은 주소를 나눠 쓰는 공격자는 그 주소의 **조용한** 짝(세 기기 모두 미참여 2분 · 참여 10분 넘게 sync 없음)을 `pair/start` 로 지울 수 있다. 차를 세우고 휴대폰 · 워치까지 꺼 둔 짝이 그렇다. 지워진 짝은 사용자가 차의 새 번호로 다시 짝지어야 한다. 휴대폰 · 워치 가운데 하나라도 sync 하면 지워지지 않는다.
- 상태는 메모리에만 있어 서버를 다시 켜면 모든 짝이 사라지고 앱은 401 을 받아 다시 짝짓는다. 여러 프로세스 · 여러 대로 늘리면 계수기와 짝을 나눠 갖지 못한다(한 프로세스 전제).
- 동시 연결 상한은 서버 전체 하나다. 주소별 연결 상한은 프록시에서 건다.

## 시험

```bash
python3 -B -m unittest discover -s server/guardian-relay -p 'test_*.py'
```

`test_limits.py` 는 남용 제한(각 문턱 바로 아래 통과 · 문턱에서 막힘 · 시간이 지나면 풀림 · 시연 흐름은 안 막힘 · 계수기 상한과 밀어내기 · 주소별 짝 상한과 조용한 짝 밀어내기 — 차만 조용한 짝 · 이웃 짝 지우기 재현) · `--trust-proxy` 유무에 따른 주소 선택 · IPv6 묶기 · 동시 연결 상한 · 느린 요청 마감 · 마감 감시가 다시 건 마감을 자르지 않음 · 벽시계를 뒤로 돌려도 음수 나이가 없음을 확인한다.

중계를 바꾼 뒤 통합 시험은 `--rerun` 으로 돌린다(`relay.py` 가 gradle 입력이 아니어서 캐시된 옛 결과가 재사용된다).

통합 시험(`apps/guardian/integration`)의 `FakeRelay` 는 빈도 제한(429) · 주소별 짝 상한 · 단조 시계 · 연결 상한 · 읽기 마감을 흉내 내지 않는다. 이 동작은 위 서버 시험만 고정한다(앱 동결로 `FakeRelay.kt` 는 고치지 않음).

시험은 저장소 단위(가짜 시계)와 임시 포트에 띄운 실제 HTTP 서버로 짝짓기 · 코드 만료 · 역할별 한 번 사용 · 토큰 오류 · 양방향 sync · 지시 전달 · ack · ttl · seq 역행 · 워치 직접 경로 · 워치 신선도(`ageMs`) · 워치 직접 경로 나이(`watchDirectAgeMs`) · 워치 테스트 멈춤(`TEST_SCENARIO_STOP`) 전달 · 휴대폰 화면 응답(`responseAt`)을 차 peer 로 전달 · 차 화면 표시 설정(`carDisplay`)을 차 peer 로 전달 · 차 → 휴대폰 테스트 요청(`TEST_REQUEST`) 전달 · 꺼짐 flow 스냅숏 통과 · 새 코드 발급 · 짝 종료 · 본문 · 큐 · ttl · id 경계값 · 짝 64개 상한 · 소켓 제한 시간 · 짝 없는 서로게이트 · NaN 거부 · **로그에 토큰 · 위치 · 심박이 없음**을 확인한다. 시험이 띄운 서버는 시험 안에서 끈다.
