# 마주 로고 — 기다림 회전 규격 · 최종 리소스 (2026-11-09)

app-design. 사용자 결정 「R2 받침 채택」과 PM 조건부 채택(실제로 기다리는 순간에만 세 마디 테두리가 천천히 돌고, 운전자 점은 멈춤)에 따른 규격이다. 뜻은 「세 기기가 운전자 곁을 돈다」다.

## 1. 한눈에

| 항목 | 값 |
|---|---|
| 도는 것 | 세 마디 테두리 `ic_logo_ring` 만. 운전자 점 `ic_logo_dot` 은 멈춤 |
| 방향 | **반시계 방향** |
| 한 바퀴 | **6초**(초당 60°) |
| 도는 동안 곡선 | 등속(`LinearEasing`) |
| 시작 | 0.6초 동안 0에서 초당 60°까지 부드럽게 가속 |
| 멈춤 | 다음 「정지 각도」(한 바퀴 단위, 0°)까지 남은 각이 60°보다 크면 등속으로 더 돌고, 마지막 60°는 2초 동안 감속해 정확히 정지 각도에 선다 |
| 깜빡임 | 없음. 투명도 · 크기 · 색은 바꾸지 않고 회전만 한다 |
| 애니메이션 끄기 | 기기 설정 「애니메이션 배율」이 0이면 돌지 않고 정지 로고(0°)를 보인다 |

## 2. 방향 — 반시계로 정한 근거

1. **받는 쪽이 앞선다.** R2 의 각 마디는 12시 기준 시계 방향으로 「오목한 시작(받는 쪽) → 둥근 끝(들어가는 쪽)」 순서로 놓여 있다. 시계 방향으로 돌리면 둥근 끝이 앞장서 앞 마디를 쫓아가는 모양이 되어 「따라잡는 · 처리 중」으로 읽힌다. 반시계로 돌리면 오목하게 벌린 받는 쪽이 앞서 나가며 둘러싸므로 「감싸며 곁을 돈다」로 읽힌다.
2. **시스템 진행 표시와 다르게.** Android 의 「불확정 진행 표시(돌아가는 원)」는 시계 방향으로 돈다[미검증 — 기기별 확인 안 함, Material 기본 동작 기준]. 방향을 반대로 두면 「불러오는 중」과의 혼동이 준다.

## 3. 속도 — 6초로 정한 근거

- 시스템 진행 원은 한 바퀴에 1~2초 안팎이라 빠르게 돈다[미검증 — 기기 · 버전마다 다름]. 6초(초당 60°)는 그보다 3배 이상 느려 「바쁘게 처리 중」보다 「곁에서 천천히 함께 있음」으로 읽힌다.
- 6초보다 느리면(예 10초) 짧은 대기(짝짓기 번호 확인 수 초)에서 움직임이 거의 안 보여 「멈춘 화면」으로 오해할 수 있다.
- R2 는 띠가 위 7 · 아래 11 이라 돌 때 두꺼운 「받침」이 원을 따라 함께 돈다. 그래서 정지 각도로 돌아왔을 때만 받침이 아래에 놓인다. 「멈출 때 정지 각도로 맞춤」이 꼭 필요한 이유다.

## 4. 시작 · 멈춤

- **시작** — 대기 화면이 나타날 때 0°에서 시작한다. 처음 0.6초 동안 가속한다(`CubicBezierEasing(0.42f, 0f, 1f, 1f)`, 0.6초 동안 18° 진행). 그 뒤로는 등속이다.
- **멈춤(같은 화면에 남을 때)** — 기다림이 끝났는데 화면이 그대로 남는 경우다(예 짝짓기 완료 문구가 같은 화면에 뜸). 지금 각도에서 다음 정지 각도(반시계로 −360° 의 배수)까지 남은 각을 구한다.
  - 남은 각이 60°보다 크면 등속으로 더 돌아 60°가 남을 때까지 간다.
  - 마지막 60°는 2초 동안 선형으로 감속해(`CubicBezierEasing(0.25f, 0.46f, 0.45f, 0.94f)`) 정확히 정지 각도에 선다.
  - 가장 오래 걸리면 5초 + 2초다. **완료 문구 · 버튼은 회전이 멈추기를 기다리지 않고 바로 보인다.** 회전 마무리는 뒤에서 조용히 끝난다.
- **멈춤(화면이 바뀔 때)** — 따로 멈추지 않는다. 화면 전환과 함께 사라진다.
- **되돌려 돌기 · 갑자기 0° 로 튀기 금지.**
- 워치 화면이 꺼지거나 저전력 표시(ambient)로 들어가면 정지 로고(0°)로 바꾼다. 다시 켜지면 0°에서 새로 시작한다.

## 5. 쓰는 화면 · 쓰지 않는 화면

**쓰는 화면** — 사람이 실제로 기다리는 순간뿐이다. 대기 문구가 늘 함께 있다.

| 기기 | 화면 | 크기 |
|---|---|---|
| 휴대폰 | 첫 실행 — 처음 설정을 준비하는 짧은 대기(있을 때만) | 96dp |
| 휴대폰 | 짝짓기 — 6자리 코드를 띄우고 워치 · 차의 확인을 기다리는 동안 | 72dp |
| 휴대폰 | 연결 중 — 워치 · 차와 다시 연결을 시도하는 동안(시도 중일 때만) | 72dp |
| 워치 | 짝짓기 대기 · 연결 중 | 48dp(지름 192~227dp 원 화면의 위쪽 안전 영역 안) |
| 차(Pleos) | **정차 중** 짝짓기 번호 화면만 | 96dp(밀도 1 가정) |

**쓰지 않는 화면.**
- 앱 아이콘 · 런처 · 알림 작은 아이콘 · 머리 막대 로고 · 시작 화면(splash) — 정지 로고만 쓴다.
- 감시 중(상시 상태) — 계속 돌면 「무언가 처리 중」으로 오해할 수 있고 배터리도 쓴다. 상태는 기존 상태 표시가 맡는다.
- 경보 1 · 경보 2 · 「괜찮아요」 응답 · 결과 · 정차 뒤 119 작성 안내 · 보호자 알림 결과 화면.
- 실신 테스트 모드 · 테스트 실행 중 · 착용 확인 · 워치 신호 없음 · 연결 끊김(오류 상태 — 기다림이 아니다).
- **차의 주행 중 모든 화면.** 정차 중 짝짓기 화면에서 돌다가 주행이 시작되면(`CarUxRestrictions` 가 제한으로 바뀌면) 즉시 정지 로고로 바꾼다. 이때는 감속 없이 바꾼다 — 주행 중 시선을 끄는 움직임을 남기지 않는 것이 먼저다.

## 6. 애니메이션 끄기

- Android 설정 「개발자 옵션 · 접근성 — 애니메이션 삭제(애니메이터 길이 배율 0)」이면 돌지 않는다. 휴대폰 · 워치 · 차 모두 같다.
- 판단 — `Settings.Global.getFloat(contentResolver, Settings.Global.ANIMATOR_DURATION_SCALE, 1f) == 0f` 이면 정지 로고를 그린다. Compose `infiniteRepeatable` 은 배율 0에서 끝 값으로 튈 수 있으므로 이 값을 직접 보고 애니메이션을 만들지 않는다.
- 접근성 — 테두리 · 점 그림은 꾸밈(`contentDescription = null`)이다. 뜻은 옆의 대기 문구가 전한다(TalkBack 은 문구만 읽는다).

## 7. 구현 메모 (app-phone · app-wear · fe-dev)

```kotlin
// 기다림 로고 — 세 마디만 반시계로 돈다, 점은 멈춤
Box(Modifier.size(size), contentAlignment = Alignment.Center) {
    Image(painterResource(R.drawable.ic_logo_ring), null,
        Modifier.fillMaxSize().graphicsLayer { rotationZ = -angle /* 반시계 */ })
    Image(painterResource(R.drawable.ic_logo_dot), null, Modifier.fillMaxSize())
}
```

- `ic_logo_ring` · `ic_logo_dot` 은 같은 64 캔버스이고 회전 중심은 캔버스 중심(32,32)이다(= 108 캔버스의 54,54 = 세 마디 바깥 원의 중심). `graphicsLayer` 의 기본 회전 중심(가운데)과 맞는다. 0°에서 두 그림을 겹치면 정지 로고(R2)가 된다(역변환 렌더로 확인).
- `ic_logo_ring` 에는 `android:name="ring"` · `pivotX/Y=32` 그룹이 있어 AnimatedVectorDrawable 로도 돌릴 수 있다. 그래도 위 시작 · 멈춤 규칙을 지키려면 Compose `Animatable` 이 쉽다.
- 밝은 · 어두운 두 벌은 `drawable/`(밝은 바탕 — 마디 #2A2F3F, 점 #4D6AB3) · `drawable-night/`(어두운 바탕 — 마디 #FFFFFF, 점 #BFD2FF)에 같은 이름으로 있다. 차가 테마와 무관하게 어두운 바탕이면 night 쪽 색을 쓰도록 리소스 한정자를 맞춘다.

## 8. 닮음 위험(불러오는 중 원)과 줄이는 방법

세 마디 원이 돌면 그 자체로 「불러오는 중」 원과 같은 범주의 움직임이 된다. 이 위험은 피할 수 없고, 아래 조건으로 줄인다.
1. 시스템 진행 원보다 3배 이상 느리게(6초) 돈다.
2. 반대 방향(반시계)으로 돈다.
3. 가운데 운전자 점이 멈춰 있어 「빈 원이 도는 진행 표시」와 모양이 다르다.
4. 마디 길이가 늘었다 줄었다 하지 않는다(Material 불확정 진행 원은 호 길이가 변한다).
5. 실제 대기 화면에서만, 대기 문구와 함께 쓴다.

그래서 사용자는 이것을 「기다리는 중」으로 읽는 것이 맞고, 그 순간에만 나오므로 오해가 아니라 뜻이 맞는 쓰임이다. 남는 위험은 「기다림 = 로고가 돈다」가 굳어 정지 아이콘까지 「불러오는 중」으로 보일 수 있는 점이다. 그래서 감시 중 같은 상시 화면에서는 돌리지 않는다.

- 11-08 `logo-adsum-final/android-res/` 와 이름 · 구성이 같다. 덮어쓰면 끝난다.
- **다른 점은 글자 로고 이름 하나다.** 11-08 의 `ic_wordmark_adsum` · `ic_wordmark_adsum_ko` 는 내용이 Maju 로 바뀌므로 `ic_wordmark_maju` · `ic_wordmark_maju_ko` 로 이름을 바꿨다. 코드의 `R.drawable.ic_wordmark_adsum` 참조(phone `PleosTopBar` · car 머리글)를 바꾸고 옛 파일을 지운다.
- 비율 — 글자 로고 영문은 `ic_wordmark_maju.xml` 머리 주석에 적힌 비율대로 쓴다(높이 16dp 기준 폭이 width 값). 기호 `ic_logo_mark*` 는 높이 16dp다.
- 마디 · 점은 채움 path(stroke 없음)라 tint 를 걸면 모두 한 색이 된다.

## 10. [미검증]

- 실제 기기(Note10 · 갤럭시워치 · Pleos 에뮬레이터)에서 회전 · 정지 각도 맞춤 · 애니메이션 배율 0 동작을 보지 않았다. aapt2 compile 만 했고 앱 빌드는 하지 않았다.
- 시스템 진행 원의 방향 · 속도는 Material 기본 동작에 기댄 판단이다.
- 차 밀도 1 가정, 워치 48dp 가 원 화면 위쪽 안전 영역에 들어가는지는 화면별 배치에서 다시 본다.
- 「첫 실행 대기」 화면이 지금 앱에 있는지는 확인하지 않았다. 없으면 쓰지 않는다.
