# Maju(마주) · 운전자 무응답 확인

> 운전 중 워치 심박이 크게 느려지면 운전자에게 응답을 묻고, 답이 없으면 차 상태를 담아 보호자에게 알리는 Pleos 차 앱과 갤럭시 휴대폰 · 워치 동반 앱의 시제품입니다.

현대자동차그룹 차량용 앱 개발 공모전(Pleos Connect · App Market) 1차 출품작입니다. 앱 안의 기능 이름은 「운전자 무응답 확인」입니다.

**먼저 알려 드립니다.** 이 앱은 의료기기가 아닙니다. 건강 상태를 가려내지 않고, 차를 제어하지 않으며, 119 에 스스로 신고하지 않습니다. 모든 상황을 알아차리지는 못합니다. 관찰한 사실을 전하고 사람이 판단하게 합니다. Pleos 탑재 실차로는 시험하지 못했습니다.

**심사위원께.** 제출한 release APK 는 **휴대폰 단독으로만 동작합니다.** 휴대폰 APK 로 처음 설정과 휴대폰 단독 테스트가 동작하도록 만들었습니다(제출 빌드를 기기에서 끝까지 돌린 기록은 아직 없습니다 · [기기 확인 날짜 — PM]). 워치 · 차 APK 는 중계 서버가 있어야 이어지는데, 공개 중계 서버는 두지 않았습니다. 세 기기가 이어지는 모습은 시연 영상(유튜브에 올린 뒤 이 자리에 주소를 넣습니다)에서 보실 수 있습니다. 설치 방법은 [APK 설치 안내](docs/apk-install-guide.md)에 있습니다.

---

## 무엇을 하나 — 세 단계

| 단계 | 언제 | 무엇을 |
|---|---|---|
| 1. 의심 신호 | 워치 심박이 크게 느려짐(1분에 40회 미만이 10초 이어짐) | 운전자에게 응답을 묻습니다. 주행 중에는 차 화면 한 줄과 음성, 워치 진동으로 묻고 **워치 버튼 하나로 답합니다.** 정차하면 차 화면에 「괜찮아요」 버튼이 하나 생깁니다 |
| 2. 응답 확인 | 첫 경보 뒤 35초 | 응답하면 감시를 이어 갑니다. 보호자에게 이미 문자가 나갔다면 취소 문자를 보냅니다 |
| 3. 무응답 연락 | 35초 동안 응답 없음 | 위치 · 차 상태 · 응답 없음 경과를 담아 **보호자에게 문자**를 보냅니다. 차가 멈춰 있으면 휴대폰에 119 문자 작성 화면을 여는 버튼을 띄웁니다. **보내기는 사람이 누릅니다** |

- 주행 중에는 차 화면에 버튼이 없고, 휴대폰도 조작을 잠급니다(「주행 중 · 휴대폰 조작은 정차한 뒤에 하세요」).
- 기능은 기본 꺼짐이고, 동의 세 가지가 모두 있어야 켜집니다.
- 정차는 기어 P 이거나 시동이 꺼진 상태로 봅니다. 주차 브레이크만으로는 정차로 보지 않습니다(기어를 읽지 못하는 경우의 규칙은 [프로토콜 계약](contracts/guardian/protocol.md) §4.2).
- 한 번 느린 심박으로 본 뒤에는 1분에 45회 이상이 3초, 또는 40회 이상이 5초 이어져야 풀립니다. 40회 근처에서 오르내릴 때 판정이 켜졌다 꺼졌다 하지 않게 한 것입니다. 응답한 뒤 다시 묻는 것은 마지막 정상 판정 뒤 느린 판정이 8초 이어질 때이고, 워치를 벗은 상태가 10초 이어지면 감시가 꺼지고 착용 확인을 안내합니다.
- 시간 값(경보 1 진동 15초 · 경보 2 소리 20초)은 모두 추정값이고 실측으로 정합니다.

**대상과 대상이 아닌 것.** 심박이 크게 느려졌는데 응답이 없을 때만 다룹니다. 워치 신호가 아예 끊기는 경우는 지금 경로에서 「워치 신호 없음」 안내에 그칩니다(아래 「한계」). 저혈당 · 발작 · 졸음 · 뇌졸중처럼 심박이 크게 느려지지 않는 경우는 이 앱의 규칙으로 알 수 없습니다.

## 세 기기 구조

차가 흐름을 정하고, 휴대폰이 연락하고, 워치가 신호를 줍니다. 차 앱은 문자를 보낼 수 없고 워치와 직접 이어지지 않아, 중계 서버와 휴대폰 동반 앱을 둡니다.

```
   ┌────────────┐   심박 · 착용 상태 · 버튼 응답
   │   워치     │ ─────────────────────────────┐
   └────────────┘                              ▼
                                      ┌──────────────────┐
   ┌────────────┐ 상태 · 지시 · 차 위치 │   중계 서버       │
   │  휴대폰    │ ◀──────────────────▶ │ 2초마다 동기화    │
   └─────┬──────┘                      │ 역할별 최신 1건만 │
         │                             │ 메모리에, 로그에  │
         │ 보호자 문자(SMS)            │ 값 없음           │
         │ 119 작성 화면(사람이 보냄)  └────────▲─────────┘
         ▼                                      │ 상태 · 지시 · 차 내비 위치(위치 동의 때만)
     보호자 · 119                       ┌───────┴────────┐
                                        │  Pleos 차 앱    │
                                        │ 주행 · 정차 · 경보│
                                        └────────────────┘
```

| 부분 | 역할 | 코드 |
|---|---|---|
| Pleos 차 앱 | 흐름(상태 기계)의 주인, 차량 상태, 차 안 경보 · 음성 · 한 줄 화면, 보호자 문자 요청(휴대폰이 보낸 기록을 볼 때까지 다시 실음), 「휴대폰 연결 끊기」 | `apps/guardian/car/` |
| 휴대폰 동반 앱 | 등록 · 동의, 보호자 문자 조립과 발송 · 보낸 기록, 보내지 못한 문자 다시 보내기, 알람, 119 작성 화면, 차가 끊기거나 다시 뜨거나 연결이 만료되면 사건 넘겨받기, 차에서 온 문자 요청의 상한과 글자 거르기, 휴대폰 단독 테스트 | `apps/guardian/phone/` |
| 워치 앱 | 심박 측정(화면이 꺼져도 유지), 진동 · 소리, 버튼 응답(응답 번호), 지금 울리는 경보 알리기, 「운전 중」 표시 | `apps/guardian/watch/` |
| 공용 로직 | 신호 관문 · 상태 기계 · 문자 양식 · 프로토콜(안드로이드 의존 없음) | `apps/guardian/shared/` |
| 통합 시험 | 세 앱의 로직을 가짜 중계 · 가상 시계로 맞물려 시험 | `apps/guardian/integration/` |
| 중계 서버 | 짝짓기와 2초 동기화. 허용 표에 있는 지시만 전달합니다. 역할별 최신 1건만 메모리에 두고, 연결을 끝내거나 24시간이 지나면 지웁니다. 파이썬 표준 라이브러리만 사용 | `server/guardian-relay/` |
| 프로토콜 계약 | 세 앱과 중계가 주고받는 형식, 지시 허용 표 | `contracts/guardian/protocol.md` · `contracts/guardian/command-roles.json` |

생체 신호를 차로 나르는 공식 경로는 공개 문서에서 찾지 못했습니다. 워치 → 중계 → 차는 이 프로젝트가 만든 자체 서버 경로입니다. 중계를 지나는 위치는 위치 동의가 있을 때만 읽는 차의 내비 위치(차 → 중계 → 휴대폰)이고, 휴대폰 위치는 중계로 보내지 않습니다.

**보호자 문자가 나갔는지는 휴대폰 기록으로 확인합니다.** 차는 문자 요청을 낸 것만으로 「보냄」으로 치지 않습니다. 휴대폰의 보낸 기록(보냄 · 보내지 않음)이 차에 보일 때까지 같은 요청을 다시 싣고, 겹친 요청은 휴대폰이 사건 단위로 한 번만 보냅니다. 그래서 차 음성은 완료형을 쓰지 않습니다. 「보호자에게 알림을 보냅니다」라고 말하고, 휴대폰 연결을 확인하지 못하면 「휴대폰 연결을 확인하지 못해 보호자 알림이 늦어질 수 있습니다」라고 말합니다. 휴대폰 기록이 확인되면 차 화면 줄만 「보호자에게 알림 보냄」으로 바뀌고, 보내지 못했으면 정차 화면에 「보호자 알림을 보내지 않았습니다 · 휴대폰을 확인하세요」가 뜹니다.

**보내지 못한 문자는 다시 보냅니다.** 휴대폰이 보호자 문자를 보내지 못하면 사건이 이어지는 동안 60초마다, 처음 시도부터 10분까지 다시 보냅니다. 운전자가 응답하거나 같은 사건의 취소가 오거나 기능을 끄면 멈춥니다. 보내지 못한 문자가 있으면 정지 중 휴대폰 경보 화면에 「보호자 문자 다시 보내기」가 떠서, 기다리지 않고 바로 다시 보낼 수 있습니다. 문자를 놓치는 것보다 겹치는 편이 낫다는 원칙으로 정했습니다.

**차가 끊겨도 휴대폰이 사건을 이어 갑니다.** 차에서 오는 신호가 10초 넘게 끊기거나, 차 앱이 다시 떠 사건이 사라지거나, 연결이 만료되면 휴대폰이 그 사건을 넘겨받습니다. 휴대폰은 차가 낸 문자 요청과 자기 기록을 사건 단위로 맞춰, 차는 냈다는데 기록에 없으면 10초 뒤 스스로 보내고, 보냈는데 운전자가 응답했으면 취소 문자를 보냅니다. 다시 뜬 차는 휴대폰의 흐름을 볼 때까지(최대 6초) 새 경보를 열지 않아, 두 기기가 서로 다른 사건을 쥐지 않게 했습니다.

**차에서 온 문자 요청에는 상한을 둡니다.** 차 쪽 연결이 잘못 쓰이거나 고장 나도 위치가 든 문자가 보호자에게 잇달아 가지 않도록, 차의 요청으로 나가는 보호자 문자(휴대폰이 넘겨받은 사건 포함)는 10분에 3통 · 24시간에 10통까지 보내고, 에어백 전개 문자는 같은 값을 따로 셉니다. 상한에 걸린 문자는 보내지 않고 휴대폰에 「짧은 시간에 차에서 온 문자 요청이 많아 보호자 문자를 보내지 않았습니다」를 띄우며, 홈의 「보낸 문자 기록」에 「문자 상한」으로 남깁니다. 휴대폰이 스스로 연 사건의 문자와 취소 문자는 세지 않고, 사람이 누른 다시 보내기는 상한에 막히지 않습니다. 차에서 온 글자 칸(주소 등)은 허용한 글자와 길이로 거르고, 전화번호나 링크처럼 보이는 칸은 문자에서 뺍니다. 받는 번호는 늘 휴대폰에 저장한 보호자 번호입니다. 차의 요청이라도 시작된 지 10분이 넘은 사건의 문자는 보내지 않고, 새로 연결된 휴대폰은 연결 전에 시작돼 본 적 없는 사건의 문자를 보내지 않습니다.

**워치 경보를 맞춥니다.** 판정을 맡은 기기(차 또는 휴대폰)는 동기화 때마다 워치가 지금 어느 사건의 어느 단계 경보를 울리는지 받아, 울려야 하는데 안 울리면 시작을, 끝났는데 울리면 정지를 10초에 한 번 다시 보냅니다. 워치는 경보에 붙은 사건 식별값으로 이미 멈춘 사건의 시작을 버립니다. 워치 버튼 응답은 누를 때마다 올라가는 응답 번호로 읽어, 워치 시계가 뒤로 가도 응답을 놓치지 않게 했습니다.

## 쓰는 SDK · 라이브러리

| SDK · 플랫폼 | 쓰는 곳 | 상태 |
|---|---|---|
| `android.car` 속도 · 기어 · 주차 브레이크 · 시동(`IGNITION_STATE`) · 주행 제한(UX Restrictions) | 주행 · 정차 구분(기어 P · 시동 꺼짐), 주행 중 버튼 숨김 | 속도 · 기어 · 주행 제한은 에뮬레이터 확인. 시동 값은 쓰는 Pleos 에뮬레이터에 속성이 없어 시험만(11-14 차 앱 기록) |
| Pleos Vehicle(2.3.2) — 브레이크 페달 · 에어백 · 착석 | 에어백 전개 때 보호자 문자 | 시험만. 에어백 값은 쓰는 Pleos 에뮬레이터가 지원하지 않아 기기로 확인할 수 없었습니다(11-13 차 앱 기록) |
| Pleos NaviHelper(3.0.5) | 차 현재 위치(위치 동의 때만), 가까운 응급실 검색 화면 | 응급실 검색 화면은 Pleos 에뮬레이터 확인(11-14, 테스트 무응답 뒤 열림). 현재 위치는 시험만 |
| Pleos TextToSpeech(3.3.1, 기기 안 음성) | 주행 중 음성 경보 | 에뮬레이터에서 음성 호출 기록 있음(11-13). 실제 소리는 [미검증] |
| Android Keystore | 차의 연결 토큰 암호화 저장(AES-GCM) | 에뮬레이터 확인 |
| Health Services(1.1.0) | **지금 감시에 쓰는 워치 신호.** 심박과 착용 여부만 받습니다 | 실기기 확인 |
| Wear Compose · Wear Ongoing Activity | 워치 화면, 「운전 중」 표시 | 실기기 확인 |
| Samsung Health Sensor SDK(1.4.1) | 맥파 · 박동 간격 · 가속도 경로 | 구현 · **감시에 쓰지 않도록 잠금**(아래 「한계」) |

- 외부 길찾기 API 와 문서에 없는 내부 API 는 쓰지 않습니다. 응급실 안내는 Pleos NaviHelper 의 공개 호출입니다.
- 차 앱은 Pleos Playground Maven 저장소에서 SDK 를 받습니다(`apps/guardian/settings.gradle.kts`). 이 저장소의 접근 조건은 [미검증]입니다.
- Samsung Health Sensor SDK 파일(AAR)은 약관상 저장소에 넣지 않았습니다. 없으면 워치는 Health Services 경로로만 빌드되고, 빌드는 실패하지 않습니다.
- 출품 워치 APK 는 Samsung Health Sensor SDK 없이 빌드했습니다. 감시는 Health Services 만 씁니다.
- 현대자동차 · 삼성전자의 상표나 로고 그림은 쓰지 않았습니다. 두 회사 이름은 함께 쓰는 기기를 밝히는 사실로만 적었습니다.

## 앱이 쓰는 권한

매니페스트(`apps/guardian/{phone,watch,car}/src/main/AndroidManifest.xml`) 기준입니다.

| 앱 | 권한 | 켜기에 필요한가 | 쓰는 곳 |

## 빌드

준비물은 Android Studio(내장 JDK 사용)와 Android SDK 입니다. `apps/guardian/local.properties`(git 밖 파일)를 만들고 SDK 경로를 적습니다.

```properties
sdk.dir=<Android SDK 경로>
```

### debug — 세 기기 시연용

같은 Wi-Fi 에 중계를 띄우고, 그 주소를 `local.properties` 에 더합니다. debug 판은 이 주소 하나만 평문 HTTP 를 허용합니다.

```properties
guardian.relayBase=http://<중계를 띄운 PC 의 LAN 주소>:8095
# 차 앱은 따로 읽습니다. 없으면 에뮬레이터에서 본 호스트 PC 주소를 씁니다.
# guardian.carRelayBase=http://<호스트>:8095
```

```bash
cd apps/guardian
./gradlew assembleDebug
```

### release — 출품용

release 는 git 밖 파일 두 개를 읽습니다. 둘 다 없어도 빌드는 되지만, 서명 없는 APK 는 기기에 설치할 수 없습니다.

1. **서명.** `apps/guardian/keystore.properties` 에 `storeFile`(절대 경로) · `storePassword` · `keyAlias` · `keyPassword` 네 칸을 적습니다. 휴대폰과 워치는 같은 키로 서명해야 합니다.
2. **중계 주소(선택).** `guardian.release.relayBase=https://<호스트>` 를 `local.properties` 에 더하면 세 앱이 그 주소로 붙습니다. `https://` 가 아니면 빌드가 멈춥니다. **비우면 release 는 휴대폰 단독으로 동작합니다. 출품 APK 는 이 상태입니다.**

```bash
cd apps/guardian
./gradlew assembleRelease
```

| APK | 위치 |
|---|---|
| 휴대폰 · 워치 · 차(출품본) | `apk/maju_maju-phone_release.apk` · `apk/maju_maju-watch_release.apk` · `apk/maju_maju-car_release.apk`(공모전 규칙 「팀명_앱이름_release.apk」 · 지문은 `apk/SHA256.txt`) |
| 빌드 결과 | `apps/guardian/{phone,watch,car}/build/outputs/apk/release/` |

### 중계 서버 실행 — LAN 시험용

```bash
python3 server/guardian-relay/relay.py --bind 0.0.0.0 --port 8095
curl -s http://127.0.0.1:8095/v1/health    # {"ok":true}
```

- 파이썬 3 표준 라이브러리만 씁니다. 설치할 패키지가 없습니다.
- 메모리에만 보관하고, 끄면 짝 · 상태 · 지시가 모두 사라집니다.
- 허용 표(`contracts/guardian/command-roles.json`)에 있는 보내는 쪽 · 받는 쪽 · 지시 종류만 전달합니다. 지시 하나 8KB · 보관 최대 120초 · 받는 쪽 큐 64KB · 본문 중첩 32단계까지만 받고, 응답마다 연결을 닫으며, 연결 토큰마다 동기화 빈도를 제한합니다.
- 평문 HTTP 입니다. 같은 Wi-Fi 안의 시험에만 쓰고, 공용 Wi-Fi 나 인터넷에 열지 않습니다.
- 자세한 내용은 [`server/guardian-relay/README.md`](server/guardian-relay/README.md) 에 있습니다.

## 한계와 하지 않는 것

- **의료기기가 아닙니다.** 건강 상태를 가려내지 않습니다. 웰니스 범위에 드는지는 법률 검토 전입니다.
- **차를 제어하지 않습니다.** 차를 세우거나 감속 · 조향 · 비상등을 다루지 않습니다. 공개 API 가 없고, 비상등은 음성으로 안내만 합니다.
- **119 에 자동으로 보내지 않습니다.** 차가 멈춘 뒤 사람이 작성 화면을 열고, 사람이 보내기를 누릅니다. 개발 · 시험 · 시연에서 실제 119 로 문자 · 전화를 보낸 적이 없습니다.
- **공개 중계 서버가 없습니다.** 위치 · 건강 관련 정보를 다루는 서버라, 암호화 통신 · 연결 번호 대입 막기 · 위치정보법 검토를 갖추기 전에는 열지 않습니다.
- **release 범위.** 그래서 출품 release APK 는 휴대폰 단독으로만 동작합니다(처음 설정 · 동의 · 보호자 등록 · 휴대폰 단독 테스트). 제출 빌드를 기기에서 끝까지 돌린 기록은 아직 없습니다([기기 확인 날짜 — PM]). 워치 · 차 release APK 는 혼자서는 감시를 시작하지 못합니다. 세 기기 시연은 같은 코드의 debug 판을 시험용 LAN 중계에 붙인 것입니다.
- **심박이 크게 느려질 때만 묻습니다.** 지금 감시 경로는 심박만 받아 1분에 40회 미만이 10초 이어질 때 응답을 묻습니다. 신호가 아예 끊기면 「워치 신호 없음」 안내에 그치고, 경보나 보호자 문자로 이어지지 않습니다. 실제로 맥박이 끊길 때 워치가 어떤 값을 내는지는 [미검증]입니다.
- **맥파 경로를 잠갔습니다.** 지금 감시는 Health Services 의 심박만 받아, 느린 맥과 착용 확인만 볼 수 있습니다. 그래서 앱 화면에 신호 신뢰가 낮다고 표시합니다. Samsung Health Sensor SDK 경로는 기록 품질은 좋았지만, 앉아 있는 기록을 지금 문턱으로 재생하자 경보가 잦아 감시에 쓰지 않도록 잠가 두었습니다(`MONITOR_READY = false`). 이 SDK 의 배포에는 삼성 파트너 승인이 필요하고, 승인 전에는 개발자 모드 실기기에서만 돕니다.
- **실제 사건으로 시험하지 않았습니다.** 몸으로 재현하는 시험은 위험해서 하지 않습니다. 경보 흐름은 화면에 「테스트 · 실제 상황 아님」을 띄운 테스트 시나리오 신호로만 확인했습니다. 응답한 경우는 실주행 4 에서 세 기기로 확인했고, 응답하지 않은 경우는 휴대폰 단독 기기 시험과 세 앱 통합 시험으로만 확인했습니다. 보호자 휴대폰에 문자가 도착한 기록은 없습니다.
- **재부팅 뒤 다시 켜짐.** 휴대폰을 다시 켜고 잠금을 풀면 앱을 열지 않아도 감시가 다시 켜집니다(11-13 실기기, 부팅 완료부터 약 1분). 잠금을 풀기 전에는 다시 켜지지 않습니다. 이때 위치까지 받으려면 「위치 항상 허용」이 필요합니다.
- **11-14 새벽 변경은 기기로 확인하지 않았습니다.** 문자 전달 확인 · 다시 보내기 · 넘겨받기 · 문자 상한 · 워치 경보 맞추기 · 판정 규칙 변경은 단위 · 통합 시험으로만 확인했습니다. Pleos 에뮬레이터에는 시동 · 에어백 속성이 없어 이 두 값에 기대는 동작은 기기로 볼 수 없습니다.
- **연결이 끊긴 동안의 응답.** 사건 중 연결이 만료되거나 중계가 다시 시작되면, 다시 연결하기 전까지 차 화면의 「괜찮아요」가 휴대폰에 닿지 않습니다. 그래서 보호자 문자가 나가고, 다시 연결한 뒤에 취소 문자가 갑니다.
- **연결이 만료된 뒤의 워치.** 워치는 중계를 거쳐서만 경보를 받습니다. 연결이 만료되면 보호자 문자는 휴대폰이 넘겨받아 보내지만 워치로는 경보가 가지 않고, 휴대폰에는 「연결 기간(24시간)이 끝났습니다 · 차 화면 코드로 다시 연결하세요」 안내가 뜹니다.
- **워치 앱을 다시 설치한 직후.** 몇 초 안에 경보와 누름이 겹치면 첫 누름을 응답으로 읽지 못할 수 있습니다. 늦게 도착한 옛 값이 연달아 오는 드문 경우에는 누르지 않은 응답으로 읽힐 수 있습니다(무작위 시험 34.8만 번 누름 가운데 6번). 설치마다 바뀌는 값을 워치가 함께 보내면 둘 다 닫히며, 제출 뒤 할 일로 남겼습니다.
- **차 앱이 다시 뜬 직후의 에어백.** 다시 뜬 차는 휴대폰 설정을 받을 때까지(최대 6초) 에어백 전개를 쥐고 있다가 사고로 엽니다. 그래서 문자에 적히는 사고 시각이 최대 6초 늦을 수 있고, 그 6초 안에 설정을 받지 못하면 그 전개는 사고로 열리지 않습니다. 앱이 시작할 때 이미 켜져 있던 에어백 값은 사고로 열지 않습니다. 그래서 앱이 뜬 뒤 에어백 값을 「꺼짐」으로 한 번 읽기 전(보통 첫 2초쯤, 차가 값을 주지 않으면 그 동안 내내)의 전개는 사고로 열리지 않습니다. 시동을 걸 때마다 사고 문자가 나가는 것을 막으려는 선택입니다.
- **문자 상한의 빈틈.** 에어백 전개 문자는 다른 문자와 따로 세어 10분 3통 · 24시간 10통까지 나갑니다. 이 상한은 차에서 온 문자 요청에만 걸리고, 휴대폰이 스스로 연 사건의 문자에는 걸리지 않습니다. 차 역할을 하루 넘게 쥔 쪽이 어제 보낸 문자를 다시 요청하면 하루 상한을 넘길 수 있는 결함이 남아 있습니다(내부 보안 점검 11-14, 공개 중계 전에 닫을 항목). 상한 때문에 미뤄진 자동 다시 보내기는 처음 시도 뒤 10분 안에 칸이 풀리지 않으면 자동으로는 나가지 않습니다. 10분 안이면 정지 중 「보호자 문자 다시 보내기」로 보낼 수 있습니다.
- **차에서 온 글자 칸 거르기의 빈틈.** 한글로 적은 번호, 자모나 닮은 글자를 섞은 번호, 14로 시작하는 일부 대표번호 꼴은 거르지 못합니다. 반대로 1500~1899 의 도로 번호 뒤에 4자리 숫자가 붙은 주소는 대표번호로 보여 주소 칸이 빠집니다(좌표 줄은 남습니다). 차가 휴대폰 화면에 띄우는 한 줄 안내는 아직 이 거르기를 거치지 않습니다.
- **연결 전 사건 막기의 빈틈.** 시작 시각을 확인할 수 없는 사건(차가 중계 시각을 받기 전에 연 사건)은, 진행 중이면 새로 연결된 휴대폰도 문자를 보내도록 두었습니다. 연결 직전에 시작된 실제 사고의 문자를 막지 않으려는 선택이고, 그만큼 좁은 빈틈이 남습니다.
- **넘겨받은 정차.** 휴대폰이 정차 중인 사건을 넘겨받은 뒤 GPS 속도를 받지 못하면(지하 · 실내 등), GPS 가 움직임을 보일 때까지 정차로 봅니다.
- **받아들인 한계.** 휴대폰 · 워치의 연결 토큰은 백업 제외만 하고 암호화하지 않았습니다.

## English summary

**Maju** is a prototype Pleos in-car app with Galaxy phone and watch companion apps. When the watch heart rate becomes very slow while driving (below 40 bpm for 10 seconds), it asks the driver to respond; if there is no response, it texts a guardian with vehicle status. If the watch signal is lost entirely, the current build only shows a "no watch signal" notice. It is not a medical device, does not control the vehicle, and never contacts emergency services on its own. The submitted release APKs run **phone-only**, because no public relay server is operated; the three-device setup is shown in the demo video using debug builds on a local relay. Tested on the Pleos emulator, a Galaxy Note10 and a Galaxy Watch, including one 32-minute on-road run inside a regular car with phone GPS speed fed to the emulator, not on a real Pleos vehicle. The submitted watch APK is built without the Samsung Health Sensor SDK.
