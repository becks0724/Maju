## 0. 전제 — [미검증]

- **앱 영역** — 캡처를 재 보면 왼쪽 순정 계기 칸이 x 0~853, 위 상태 막대가 y 0~90, 아래 공조 바가 y 1300~1440 이다. 우리 앱은 **x 855~2560 · y 90~1300, 약 1705×1210px** 안에 그린다. 지시서의 「약 1408 너비」와 다르다. 그래서 목업에서 1408px 도 함께 확인했다. 이 설계는 **폭 1200px 이상이면 두 칸, 그보다 좁으면 한 칸**으로 그린다(weather-split 과 같은 문턱).
- **밀도** — 차 앱에는 `UI_SCALE` 이 없다. 이 문서는 기본 밀도 1.0(1dp = 1sp = 1px)으로 가정한다. 캡처의 「확인 중」(44sp)이 약 44px 로 보여 이 가정과 맞는다. `wm density` 실측으로 확정해야 한다.
- 주행 · 정차는 지금 코드의 `setupOk`(NO_SETUP 제한 없음 + 정차, 상태 기계 디바운스 값)를 그대로 쓴다. 이 문서의 「정차 중」은 `setupOk == true`, 「주행 중」은 `false` 를 뜻한다.

## 1. 화면 흐름 (차)

```
[앱 시작]
  중계 주소 없음 ─▶ RELAY_MISSING(그대로)
  짝 없음 / 번호 살아 있고 안 붙은 역할 있음 ─▶ 번호 화면(그대로, 주행 중이면 PAIR_DRIVING 한 줄)
  짝 있음 ─▶ 상태 화면
      정차 중 ─▶ C1 정차 상태(두 칸 = 왼쪽 상태 · 연결 줄 / 오른쪽 워치 칸 + 「테스트 시작」)
                  「테스트 시작」 ─▶ C1' 확인 창(「시작」 · 「취소」) ─▶ 휴대폰에 요청 ─▶ 테스트 표시가 켜지면 C1 + 테스트 띠
      주행 중 ─▶ C2 주행 한 줄(상태 한 줄 + 워치 한 줄, 버튼 0)
      흐름 경보(SHOW 지시의 line 있음) ─▶ C3 경보 화면(모든 것을 덮음, 생체 칸 · 워치 줄 숨김)
                  정지 화면이면 「괜찮아요」 1개, 주행 중이면 버튼 0
```

- 우선순위는 **경보 > 중계 주소 없음 > 번호 화면 > 상태 화면**이다. 지금 `CarApp` 의 `when` 순서와 같다. 생체 칸은 상태 화면 안에만 있고 경보가 오면 사라진다(결정 ② 「경보 화면이 우선」).
- 테스트 중이면 모든 화면(경보 포함) 맨 위에 청록 띠 「테스트 · 실제 상황 아님」을 둔다.

## 2. 상태별 화면 구성

지금 표(404cd9c · 13c544c)를 넓힌 것이다. 굵은 글씨가 새로 생기거나 바뀌는 부분이다.

| 상태 | 정차 중(`setupOk`) | 주행 중 |

| 서버 끊김(`linkOk == false`) | **「서버 연결 끊김 · 다시 연결하는 중」 + 둘째 줄 「끊긴 동안은 차 화면과 음성으로만 안내합니다」**, 연결 줄 3개(서버 ▲ 끊김), **워치 칸 = 「워치 신호 없음」**, 테스트 입구 흐림 | **「서버 연결 끊김」** |
| 둘 다 붙음 · 흐름 OFF | **정차 문구(§7-1 정차 열)** + 연결 줄 3개 + 새 연결 번호 + **워치 칸** + 테스트 입구 흐림(사유 줄) | **주행 문구(§7-1 주행 열, 원인만)** + 워치 한 줄(원인이 워치면 생략) |

| **숨김(휴대폰 스위치 켬)** | 워치 칸의 심박 · 맥박 신호 값 자리에 「휴대폰에서 숨김」. 착용 · 마지막 갱신과 워치 줄의 받는 길은 그대로 | **「워치 착용」**(숫자 없음) |
| **숨김 설정 모름**(이번 실행에서 휴대폰 값을 아직 못 받음) | 심박 · 맥박 신호 자리에 「휴대폰 설정 확인 중」 | 「워치 착용」 |
| **워치 신호 없음**(`ageMs` > 30초 또는 워치 값 없음) | 워치 줄 ▲ 「신호 없음」, 워치 칸 큰 글자 「워치 신호 없음」, 값 줄은 「—」, 마지막 갱신 「30초 넘게 받지 못함」 | 「워치 신호 없음」(상태 한 줄이 이미 워치 원인이면 생략) |

| **측정값 없음**(동의 있음 · `hr` null) | 심박 「측정값 없음」 | 「워치 착용」 |
| **테스트 중**(flow `test` 참) | 맨 위 테스트 띠, 워치 칸 머리에 「테스트 값」 꼬리표(워치 값 `test` 참 또는 `source == SIMULATION` 일 때), 입구 자리에 「테스트 멈추기」(§5, PM 결정 2) | 맨 위 테스트 띠 + 한 줄(값은 그대로 표시) |
| 경보(SHOW line 있음) | 경보 한 줄 · 「괜찮아요」(정지 화면만). **워치 칸 · 연결 줄 · 테스트 입구 모두 숨김** | 경보 한 줄 · 버튼 0. **워치 한 줄 숨김** |

- 「시계 미확인」(`STATUS_CLOCK_UNVERIFIED`)은 그대로 상태 한 줄 아래 작은 글씨로 둔다(정차 중만).
- 주행 중 화면에는 누를 것이 없다(터치 0회, G5). 「새 연결 번호」 · 「테스트 시작」은 정차 중에만 그린다.
- 「휴대폰 연결 끊기」(2026-11-08 감사 하3 · 운전자 교체) — 정차 화면 왼쪽 칸 「새 연결 번호」 아래 button_basic 80. 확정 정지(기어 P 또는 주차 브레이크)이고 사건이 없을 때(OFF · S0)만 그린다. 같은 조건이면 번호 화면(휴대폰 · 워치를 기다리는 중)에도 번호 · 안내 아래 같은 버튼을 둔다(2026-11-09 코드 리뷰). 누르면 확인 창(C1' 양식, 「휴대폰 연결을 끊을까요?」 · 「되돌릴 수 없습니다 · 다시 쓰려면 새 번호로 연결합니다」 · 보조 줄 「이 차 화면에 휴대폰 · 워치 상태가 더는 보이지 않습니다」 · 「끊기」). 짝짓기 · 새 번호 · 끝내기 요청이 나가 있는 동안은 숨긴다 → 번호 화면. 중계에 알리지 못하면 번호 화면에 「차에서는 끊었습니다 · 중계 기록은 24시간 뒤 사라집니다」(문구는 `CarTexts.UNPAIR_*`).

## 3. 와이어프레임 (Pleos 순정 화면 양식 — `design-system.md`)

치수는 px(= dp, §0 가정)다. 앱 영역은 1705×1210, 안쪽 여백은 48 이다. 순정 차량 설정(캡처 04)처럼 **머리 막대 + 1px 선으로 나눈 칸 + 왼쪽 맞춤**으로 그리고, 모서리는 0, 그림자는 없다.

- 워치 칸은 `surface` 바탕의 2×2 격자다(순정 04 의 카드 격자와 같은 짜임). 칸에는 아이콘 없이 라벨 + 값만 둔다. 하트 · 맥박 선 아이콘은 쓰지 않는다(design-system 5절).
- 받는 길(Wi-Fi 직접 · 휴대폰 경유)은 워치 칸이 아니라 **연결 줄의 워치 줄**에 둔다. 착용은 워치 칸이 맡는다. 그래서 워치 줄 상태는 「연결됨 · Wi-Fi 직접」 · 「연결됨 · 휴대폰 경유」 · 「신호 없음」으로 바꾼다(§7-3).
- 폭 1200 미만(분할 창 등)이면 한 칸으로 쌓는다. 순서는 상태 → 워치 칸 → 테스트 시작 → 연결 줄 → 새 연결 번호 → 고지다. 세로가 넘치면 스크롤을 허용한다(정차 중만).

### 3-2. 연결 줄 정렬 (PM 추가 입력 2 — 캡처의 들쭉날쭉 고침)

지금은 `Row` 마다 가운데 정렬이라, 「워치」 줄은 상태 글자가 길어 왼쪽으로 밀린다. 그래서 점 · 이름 · 상태의 왼쪽 끝이 줄마다 다르다. 이렇게 고친다.

- 세 줄을 **한 덩어리(`Column`)**로 묶고, 덩어리 안에서는 줄마다 **왼쪽 맞춤**으로 둔다. 두 칸 배치에서는 덩어리가 왼쪽 칸 왼쪽 끝에 붙는다. 한 칸 배치에서도 왼쪽 맞춤이다(순정 목록과 같다).
- 열은 고정한다. 글리프 열 40(글리프 28, 가운데), 이름 열 **160 고정**(Title S 32 Bold, 「휴대폰」이 약 100 이라 여유 있음), 상태 열은 나머지 폭에 왼쪽 맞춤, Body L 30 `text2` 이다.
- 줄 높이는 88 이고, 줄 사이에 1px `line` 을 둔다(순정 목록처럼). 글리프 · 이름 · 상태는 같은 기준선에 맞춘다(`Modifier.alignByBaseline()`).
- 근거 — 세로 기준선이 하나면 눈이 이름 열을 위에서 아래로 한 번에 훑는다. 상태 글자만 읽으면 되므로 1~2초 안에 읽힌다.

```
│          워치 착용 · 심박 72  Body L 30 Normal text2   │
│                                          │
└──────────────────────────────────────────┘
```

- 가운데 정렬이고, 두 줄 사이는 16 이다. 연결 줄 · 워치 칸 · 버튼 · 고지는 그리지 않는다(지금과 같다). 머리 막대는 남기되 누를 것이 없다.
- 워치 한 줄에는 맥박 신호 상태를 넣지 않는다. 주행 중 운전자가 건강 상태를 읽고 해석하게 만들지 않으려는 것이다. 신호가 끊기면 상태 기계가 경보(SHOW)를 따로 띄운다.
- 숫자 「72」는 고정폭 숫자(`tnum`)로 써서 값이 바뀌어도 글자 폭이 흔들리지 않게 한다.

### 3-5. C3 경보 (늘 어두움)

- 머리 막대를 숨기고 앱 영역 전체를 `alarmBg` #131417 로 덮는다.
- 경보 한 줄은 Headline M 56 Bold `alarmText`, 가운데 정렬, 최대 2줄이다(지금 56 그대로). 정지 화면이면 「괜찮아요」 버튼을 둔다. 높이 128, 최소 폭 480, 모서리 0, Headline S 48 Bold, 바탕 #FFFFFF + 글자 #131417(18.4:1)이다.
- 지금 버튼은 #FFB000 + 검정이다. 노랑은 Pleos `regulation_yellow` 와 우리 경보 1 단계색이라 버튼으로 읽히지 않는다. 그래서 Pleos 반전 방식(흰 채운 버튼)으로 바꾼다(design-system 2-3).
- 생체 칸 · 워치 줄 · 연결 줄은 그리지 않는다.

### 4-3. 갱신 규칙

| | 정차 중 | 주행 중 |
|---|---|---|
| 값을 바꾸는 시점 | sync 주기(2초) 그대로. 받은 값을 바로 그린다 | **한 줄 전체를 10초에 한 번만** 바꾼다. 주행으로 바뀐 첫 순간에는 바로 그리고, 그 뒤 10초마다 최신 값으로 바꾼다 |

| 움직임 | 없음. 숫자는 보간 · 페이드 · 깜빡임 없이 제자리에서 바뀐다 | 없음 |

- 정차 ↔ 주행 전환은 상태 기계의 디바운스된 값(`setupOk`)만 따른다. 그래서 전환 순간 화면이 흔들리지 않는다.

## 5. 정차 중 테스트 시작 입구

- **위치** — 워치 칸 바로 아래, 칸 폭 전체, 높이 96(터치 76 기준을 넘음)인 `inverse` 채운 버튼 「테스트 시작」이다(모서리 0, 앞에 「T」 아이콘). 상태 줄 가까이 두지 않는다. 경보 「괜찮아요」 자리(화면 가운데)와 멀어야 실수로 누르지 않는다.

## 7. 문구표 (상수 이름 제안 — 모두 「제안」, `CarTexts.all` 에 넣어 금지어 시험을 건다)

### 7-1. 상태 한 줄 — 주행 중 / 정차 중 (PM 추가 입력 3)

주행 중에는 **원인만** 적는다. 「켜세요 · 착용하세요 · 동의」처럼 휴대폰 조작이나 몸을 움직이라는 요구는 정차 중에만 쓴다(G5). 주행 중 한 줄 앞에 「꺼짐 ·」을 붙여, 지금 확인이 돌고 있지 않다는 사실이 먼저 읽히게 한다. 다만 사용자가 켰는데 워치 때문에 확인이 멈춘 두 경우(워치 신호 없음 · 착용 안 됨)는 「확인 멈춤 ·」을 붙인다 — 「꺼짐」은 사용자가 끈 것으로 읽혀 휴대폰의 「켜짐」과 어긋났다(사용자 결정 2026-11-10).

| 원인(`CarScreen.offLine` 순서) | 정차 중 상수 · 문구 | 주행 중 상수 · 문구 |
|---|---|---|
| 서버 끊김(`!linkOk`) | `STATUS_SERVER_LOST` 「서버 연결 끊김 · 다시 연결하는 중」 + `STATUS_SERVER_LOST_SUB` 「끊긴 동안은 차 화면과 음성으로만 안내합니다」 | `DRIVE_SERVER_LOST` 「서버 연결 끊김」 |
| 꺼짐(`!powerOn`) | `STATUS_OFF` 「꺼짐 · 휴대폰 앱에서 켜세요」(그대로) | `DRIVE_OFF` 「꺼짐」 |
| 동의 빠짐 | `STATUS_OFF_CONSENT` 「휴대폰 앱에서 동의가 필요합니다」(그대로) | `DRIVE_OFF_CONSENT` 「꺼짐 · 동의 필요」 |
| 워치 신호 없음 | `STATUS_OFF_WATCH_WAIT` 「워치 신호를 기다리는 중」(그대로) | `DRIVE_OFF_WATCH_WAIT` 「확인 멈춤 · 워치 신호 없음」 |
| 워치 착용 안 됨 | `STATUS_OFF_WEAR` 「워치를 착용하세요」(그대로) | `DRIVE_OFF_WEAR` 「확인 멈춤 · 워치 착용 안 됨」 |
| 켜짐(S0 이후) | `STATUS_WATCHING` 「확인 중」 | `STATUS_WATCHING` 「확인 중」 |
| 응답 뒤 휴식(S1R, 2026-11-08 PM 결정) | 상태 기계 안내 「응답 확인됨 · 쉬어 가세요」(그대로) | `DRIVE_S1R` 「응답 확인됨」 |

- **주행 문구 검사 기준(2026-11-08)** — 주행 열에 나올 수 있는 모든 문구(위 표 · §7-2 · 테스트 띠 · 경보 아닌 상태의 상태 기계 안내와 기본 문구)에 「…세요」(하세요 · 가세요 · 출발하세요 · 켜세요 등)와 「동의가 필요」가 없어야 한다(`CarBioScreenTest.drivingTextsAskNothingOfTheDriver`).

- `STATUS_LINK_LOST` 「휴대폰 연결 끊김 · 차 안 안내만 합니다」는 지운다. 이 문구는 실제로는 **서버 sync 실패**(`linkOk == false`) 때 나와서, 휴대폰이 멀쩡해도 「휴대폰 연결 끊김」이라고 잘못 알렸다. 서버가 끊기면 휴대폰 · 워치 소식이 모두 끊기므로 원인은 서버라고 쓴다. 휴대폰만 끊긴 경우는 연결 줄의 「휴대폰 ▲ 끊김」이 맡는다.
- 구현은 `CarScreen.idle` 이 `setupOk` 에 따라 두 열 가운데 하나를 고르는 것이다. 지금은 `setupOk` 와 관계없이 정차 열을 고른다.
- 짝짓기 · 중계 주소 문구(`PAIR_*` · `RELAY_MISSING`)는 바꾸지 않는다. 주행 중 번호 화면은 이미 `PAIR_DRIVING` 한 줄이다.

## 8. 휴대폰 쪽 설계

### 8-1. 「차 화면에 심박 숨기기」 스위치 — P07 · P08 홈

```
│ 연결                                        │
│  ● 차     연결됨 · 2초 전                    │
│  ● 워치   연결됨 · 착용 중 · Wi-Fi 직접        │
│  ● 서버   연결됨                             │
│ 차 화면                                      │ 15sp 머리(「연결」과 같은 모양)
│  차 화면에 심박 숨기기              [ ━━○ ]  │ 줄 56, 20sp, Switch 터치 48
│  켜면 차 화면에 심박 숫자와 맥박 신호 상태를   │ 15sp text2
│  보이지 않습니다 · 경보는 그대로 울립니다       │
│ 보호자  김○○ · 010-0000-0000(예시)           │
```

- 기본값은 **꺼짐**(= 차에 표시)이다(결정 ③).
- 주행 중(P09)에는 다른 홈 조작처럼 `enabled=false` 다. 「모름」 상태에서는 설정 조작 허용 규칙(G5)을 따라 누를 수 있다.
- 바꾸면 다음 sync(2초 안)에 차로 간다. 차는 그때부터 숨긴다. 휴대폰은 바꾼 즉시 스위치 아래에 「차에 반영하는 중」 같은 문구를 두지 않는다. 차가 받았는지를 휴대폰이 알 길이 없어서다.
- 설정 화면(spec.md 11절 9, 아직 안 그림)이 생기면 같은 줄을 그곳에도 둔다.
- 왜 홈인가 — 동승자가 탄 순간 운전자가 정차 중에 바로 찾을 수 있어야 한다. 설정 화면은 아직 없고, 동의 화면(P04)은 동의를 받는 자리라 켜고 끄는 설정을 섞으면 「동의 철회」로 오해할 수 있다.

### 8-2. P04 동의 ② 건강 관련 정보 카드

- 「받는 곳」 줄에 「연결한 차 화면(표시만 · 저장하지 않음)」을 더한다(G2 받는 자 · 목적 고지).
- 카드 안 `CONSENT_RAW_STAYS` 아래에 `CONSENT_CAR_DISPLAY` 문단(15sp `text2`)을 둔다.
- 이미 동의한 사용자는 동의 범위가 넓어진 것이므로 다시 동의를 받아야 한다(동의 문구 판 올림). 다시 받기 전까지 차에는 심박을 보이지 않는다(PM 결정 4).

### 9-2. 휴대폰(app-phone, `:phone`)

- 설정 `hideHrOnCar: Boolean = false` 를 휴대폰 안에 저장한다(다른 설정과 같은 곳). 홈 P07 · P08 에 §8-1 줄을 둔다.
- 매 sync 요청에 이 값을 싣는다(§9-3).
- P04 ② 문구를 바꾸고 동의 판을 올린다. 판이 낮은 동의로 켜져 있던 사용자에게는 다음 정차 때 P04 를 다시 보인다(PM 결정 4).
- 차가 보낸 테스트 요청(§9-3)을 받으면 P15 「테스트 시작」을 누른 것과 같은 길로 시작한다. 단, 휴대폰 자체 조건(「정차 중입니다」 확인 등)도 그대로 지킨다. 차 연결이 있으면 이동 판단이 차 기준 「정차」라 확인은 통과한다. 시작하지 못하면 ack 만 하고 테스트는 켜지 않는다(차는 15초 뒤 `TEST_NO_ANSWER`).

### 9-3. 계약(be-dev · PM — 이 문서는 필드 이름만 제안하고 계약은 고치지 않는다)

1. **숨김 설정 전달** — `PhoneSyncRequest` 최상위에 `carDisplay: {"hideHr": bool}` 를 더하고, 중계가 `PhonePeer.carDisplay` 로 그대로 싣는다. 흐름 상태와 관계없는 표시 설정이라 `flow.snapshot` 에 넣지 않는 쪽을 권한다. 다만 지금 설정(`powerOn` · `consents` · `test`)이 snapshot 에 있으니 같은 곳에 `snapshot.hideHrOnCar` 로 두는 길도 된다(be-dev 판단).
   - 차는 `peer` 가 null 이거나 `carDisplay` 가 없으면 「모름」으로 보고 숨긴다. 휴대폰이 한 번이라도 값을 보내면 그 값을 메모리에 두고, 휴대폰이 끊겨도(`peer` 는 있으나 `receivedAt` 이 오래됨) 마지막 값을 쓴다. `peer` 자체가 null 로 오면(중계 재기동 등) 마지막 값을 버리고 숨긴다(계약 §4.1, PM 결정 2026-11-02).
2. **차 → 휴대폰 테스트 요청** — 새 지시 `TEST_REQUEST`(CAR → PHONE). 시작은 `{"action":"START","scenario":"PULSE_LOST","durationMs":60000}`, 멈춤은 `{"action":"STOP"}`(PM 결정 2), `test:true` 다. 지금 계약은 「테스트 모드는 휴대폰에서만 바꾼다」(설정 절)와 `TEST_SCENARIO` PHONE → WATCH 뿐이다. 그래서 차가 직접 워치에 시나리오를 보내지 않고 휴대폰을 거친다. 보호자 테스트 문자 · 119 미리보기가 휴대폰에 있고, 워치 지시 경로(직접 경로만)를 하나로 지키려는 것이다.
3. 중계가 모르는 최상위 필드 · 지시 type 을 400 으로 거르는지 확인해야 한다. 지금 `relay.py` 검증 규칙은 읽지 않았다 [미검증].

| Pleos 1~2초 | 주행 중에는 상태 + 워치 한 줄뿐이고, 숫자 하나만 읽으면 된다. 연결 줄은 열을 고정해 세로로 한 번에 훑는다 |

## 11. [미검증]

- 앱 영역 크기 — 캡처 기준 약 1705×1210 으로, 지시서의 1408 과 다르다. 기본 밀도 1.0 가정도 `wm density` 로 확정해야 한다.
- 차 앱이 Pleos 에서 주행 중 전면에 떠 있을 수 있는지, 분할 창 폭이 얼마인지(차 화면 정책).
- `CarUxRestrictions` 가 주행 중 숫자 갱신(10초 주기)을 「움직이는 요소」로 보지 않는지.
- 실제 sync 에 `hr` 이 차까지 오는지 — 결정 ④ 순서상 베타 확인 몫이다.
- 중계가 `carDisplay` · `TEST_REQUEST` 를 통과시키는지(`relay.py` 미확인).
- 동의 범위를 넓힐 때 재동의가 법적으로 필요한지 [법률 검토 필요] — 이 설계는 보수적으로 다시 받는다.
- 밝은 테마가 차량 밤 모드와 이어지는지(weather-split 과 같은 미검증).

## 12. PM 이 정할 것

1. **숨김 스위치가 가리는 범위** — 권장은 심박 숫자 + 맥박 신호 상태 둘 다다. 착용 · 갱신은 연결 사실이라 둔다. 결정 문구가 「심박 숨기기」라 맥박 신호까지 포함할지 확인이 필요하다.
2. **차에서 「테스트 멈추기」도 둘지** — 권장은 둔다. 차에서 시작했는데 멈추려면 휴대폰을 집어야 하면 G5 취지와 어긋난다. 같은 `TEST_REQUEST` 의 `action:"STOP"` 이다.
3. **숨김 설정 전달 위치** — `PhoneSyncRequest.carDisplay`(권장) 또는 `flow.snapshot.hideHrOnCar`.
4. **동의 판 올림 · 재동의** — 기존 사용자에게 P04 를 다시 보일지(권장) 아니면 고지만 할지.
5. **경보 「괜찮아요」 버튼 색** — 지금 노랑(#FFB000)을 Pleos 반전 방식의 흰 채운 버튼(#FFFFFF + #131417)으로 바꿀지(권장, 휴대폰 · 워치도 같이).
6. **차 테스트 시나리오** — `PULSE_LOST` 60초 하나로 고정할지(권장), 차에서도 고르게 할지.
