# 운전자 무응답 확인(가칭) — 설계 v1 (2026-10-30, PM)

기획 검토 3판(팀 내부 자료, 비공개)과 팀 내부 법 준수 지침(비공개 · README 「안전 · 개인정보 원칙」에 요약)(G1~G9)를 구현으로 옮긴다. 이 문서의 숫자 기준은 모두 [추정]이고 실기기 · 에뮬레이터 실측으로 정한다.

## 0. 사용자 결정(2026-10-30 원문 요지)

- 공모전 형태는 **실기기 전체 연결**. 시험 기기는 **Galaxy Watch9 · Galaxy Note10+**, Pleos 는 **가상(에뮬레이터)** 연결로 시험.
- **삼성 SDK 를 주로**, 보완으로 **구글 SDK 참고 · 필요하면 적용**.
- **높은 dB 경보 채택**. **법 준수 가이드라인에 맞게**.
- 119 문자 양식은 G9 전체 판에 **「이 번호」 + 보호자 연락처**를 넣는다 — 보호자로 평소 지병을 확인하는 수단.
- **실신 테스트 모드** — 생체 데이터 실신 모드로 흐름을 돌리고, **119 가 아니라 보호자에게 테스트 문자**를 보낸다.
- 앰비언트 제어가 되면 **파랑 · 빨강 깜빡임 · 최대 밝기**로 야간 외부 인지 — 법 확인(조사 중) 뒤 확정.
- 휴대폰 알람의 차 스피커 출력은 **BMW 차량에서 사용자 확인**(현대 · Pleos 헤드유닛은 미확인).

하지 않는 것 — 119 자동 전화 · 사람 없는 자동 119 문자(G4), 정차 · 비상등 제어(G6), 「실신」 판정 문구(G1), 「실신 가능성」 산출(G9).

## 2. 신호 흐름과 판정 주인

```
워치 ──Data Layer(1초 요약 + 사건 즉시)──▶ 휴대폰 ──HTTP POST /v1/phone/sync(2초 + 사건 즉시)──▶ 중계
                                                                                           ▲
Pleos 차 앱 ──HTTP POST /v1/car/sync(2초)──────────────────────────────────────────────────┘
```

- 차는 푸시를 받을 수 없으므로 **sync 응답에 상대의 최신 상태와 대기 지시를 실어** 보낸다(휴대폰도 같은 방식, 베타에서는 FCM 을 쓰지 않는다 — 계정 · 외부 서비스 불필요).
- **판정 주인** — 차 앱의 마지막 sync 가 10초 안이면 **차 앱이 상태 기계 주인**(사용자 정정 「허브 = Pleos 앱」). 그보다 오래되면 **휴대폰이 대신 주인**이 되고 「차 상태 없음」을 표시 · 문자에 적는다. 두 쪽 모두 같은 `:shared` 상태 기계를 쓰고, 주인이 바뀌면 상태 · 타이머를 그대로 넘긴다(상태 스냅숏을 sync 에 싣는다).
- **베타 네트워크** — 중계는 Mac 에서 돈다. Pleos 에뮬레이터는 `10.0.2.2`, 휴대폰(Note10+)은 같은 Wi-Fi 의 Mac 주소로 붙는다. 평문 HTTP 는 **debug 빌드 · 설정한 주소만** 허용한다(network security config). 공개 운영은 HTTPS 서버 — 사용자 결정(G2, Pleos 보안 가이드).

## 3. 신호 관문(워치, `:shared` bio)

입력 — Sensor SDK `PPG_CONTINUOUS`(녹색 · 적외선 · 적색 25Hz), `ACCELEROMETER_CONTINUOUS`(25Hz), `HEART_RATE_CONTINUOUS`(1Hz, IBI 목록, 상태값). 화면이 꺼지면 묶음으로 오므로 판정 중에는 `flush()` 를 2초마다 부른다.

| 단계 | 규칙(기본값은 [추정]) | 근거 |
|---|---|---|
| 전처리 | 녹색 · 적외선을 0.5–4Hz 대역통과(2차 Butterworth, 25Hz). LED 전류 정규화는 SDK 가 값을 주지 않아 못 함 → 대신 DC 급변(센서 자동 이득)을 감지하면 기준을 다시 잡음 | 구글 Methods, Sensor SDK `PpgSet` |
| A1 진폭 급감 | 3초 창 AC(표준편차) ≤ 기준의 10% 가 3창 연속. 기준 = 직전 30초 AC 중앙값(맥이 있던 구간) | 구글 1단계(90% 급감) |
| A2 손목 정지 | 가속도 크기의 10초 표준편차 < θ. θ 는 **주행 중 θ_drive · 정차 중 θ_park 둘**, 차 진동 실측으로 정함 | 구글 1단계(10초 정지), 차 진동 [미검증] |
| A3 박동 공백 | 상태 정상(1)인데 유효 IBI 없음 4초 이상, 또는 심박 < 40 이 10초 이상 | 실신 심박 억제(무수축 3초 이상 · 30bpm 미만 서맥) |
| B 두 파장 확인 | 녹색 · 적외선 10초에서 40–220BPM 대역 신호 대 잡음비 < θ_snr 그리고 자기상관 최대(지연 0.27–1.5초) < θ_ac | 구글 2단계 |
| 착용 검사 | 심박 상태 −3 미착용 → 판정하지 않고 「착용 확인」, −2 움직임 → 보류, −8 · −10 신호 약함 → 적색 채널 · DC 로 느슨함 의심이면 「착용 확인」 | Sensor SDK 상태값 |

출력 — `NORMAL` · `CHECK_WEAR` · `PULSE_WEAK`(A1 또는 A3) · `PULSE_ABSENT`((A1 또는 A3) + A2 + B).

- **구글 SDK 보완(Health Services)** — Sensor SDK 를 못 쓰는 기기 · 상황에서는 Health Services 심박만으로 A3 만 판단하고, 판정 신뢰가 낮음을 표시한다.
- **시뮬레이션(실신 테스트 모드)** — 시나리오(정상 → 진폭 급감 → 맥 신호 소실 · 느슨함 · 미착용 · 움직임)로 같은 입력 배열을 만들어 **실제와 같은 관문 코드**에 넣는다. 관문을 건너뛰지 않는다.
- 화면 · 문자 표현은 G1 — 「맥박 신호 약해짐 · 잡히지 않음」, 「응답 확인 필요」만 쓴다.
- 5분 HRV 「전조」 모델(삼성 논문)은 학습 데이터가 없어 넣지 않는다. 기록만 남겨 나중에 검토.

## 4. 상태 기계(`:shared` flow)

입력 — 워치 판정, 응답(워치 버튼 · 손목 움직임 · 차 화면 버튼 · 휴대폰 화면(정지 때만)), 차량(속도 km/h · 기어 · 주차 브레이크 · 에어백 전개), 링크 신선도, 현재 시각. 정지 = 속도 ≤ 3km/h 이고 (기어 P 또는 주차 브레이크).

| 상태 | 들어가는 조건 | 할 일(지시) | 나가는 조건 |
|---|---|---|---|
| OFF | 동의 전 · 기능 꺼짐 · 워치 미착용 | 없음 | 동의 3종 + 켬 + 착용 → S0 |
| S0 감시 | — | 워치 연속 측정 | 판정 `PULSE_WEAK`·`PULSE_ABSENT` 이면서 주행 → S1 / 정지 → AP(정차 중 경보) |
| S1 1차 경보 | 주행 중 판정 | 워치 최대 진동 · 휴대폰 알람 최대 · 차 음성 「안전한 곳에 차를 세우세요」 · 화면 한 줄 · (승인 뒤) 앰비언트 | 응답 → S1R / 정지 → S2(경보 유지) / 35초 무응답(진동 15 + 소리 20) → S3 |
| S1R 응답함 | S1 중 응답 | 경보 멈춤, 「쉬어 가세요」 음성 1회, 정지하면 관찰 | 정지 → S2 / 10분 뒤 판정 정상 → S0 / 워치 미착용 10초 이어짐 → 꺼짐 + 「착용 확인」(2026-11-08 · 11-09 — 10초 안 깜박임은 휴식 · 재경보 간격을 그대로 둠) |
| AP 정차 중 경보 | 정지 상태에서 판정 | 경보 1(진동 15초) → 경보 2(소리 · 화면 20초) | 응답 → S2 / 무응답 → S4 |
| S2 정차 관찰 | S1 · S1R · AP 에서 정지 | 차 화면 「쉬는 중 · 괜찮아지면 다시 출발」 + 「괜찮아요」 버튼, 보호자에게 「정차 관찰 중」(선택), 워치는 정차 기준(θ_park) | T_obs(10분) 판정 정상(또는 워치 값 낡음) + 운전자 확인 → S0 / 판정 다시 → AP / 워치 미착용 10초 이어짐 → 꺼짐 + 「착용 확인」(2026-11-08 · 11-09 — 10초 안 깜박임은 휴식 · 재경보 간격을 그대로 둠) |
| S3 주행 중 무응답 | S1 에서 35초 무응답 | 경보 유지 · 남은 시간 음성 · **보호자 자동 문자(G9)** | 정지 → S4(사건 중 첫 차량 입력은 확정 정지만 즉시, 아래) / 응답 → S1R(만료와 같은 ms 면 응답 먼저 — 문자 없음) |
| S4 정차 뒤 무응답 | AP · S3 정지 | **보호자 자동 문자(보내지 않았으면)** · 차 화면 「구조 요청 중」 + 응급실 안내 · 휴대폰에 **119 문자 작성 화면(반자동)** · 「119 신고」 앱 연결 | 응답 → 보호자에게 「응답함 · 취소」 문자 → S2 |
| S5 사고 | 에어백 전개(어느 상태에서나) | 보호자 문자(사고), 순정 SOS 안내 | 운전자 확인 |

- 타이머 기본값 — 경보 1 15초, 경보 2 20초, 관찰 T_obs 10분, 응답 뒤 휴지 10분, 문자 재전송 금지(한 사건 한 번 + 취소 한 번).
- **같은 ms 는 응답이 먼저**(2026-11-08 PM 결정) — 응답과 경보 2 시작 · 35초 무응답 만료가 같은 ms 면 응답을 먼저 반영한다. 사건 문자와 취소 문자가 한 번에 나가지 않는다. 받지 않는 응답(주행 중 휴대폰 화면)이면 만료는 그대로 난다.
- **사건 도중 첫 차량 입력**(2026-11-08 PM 결정) — 그때까지 차량 입력이 없던 기계(주행으로 봄)가 사건 중 첫 입력을 받으면, **확정 정지(기어 P 또는 주차 브레이크 체결)일 때만** 디바운스 없이 정차 전이(S1 → AP, S3 → S4)를 낸다. 기어 · 주차 브레이크를 모르고 속도만으로 정지면 첫 입력이라도 5초 디바운스를 거친다(S3 → S4 는 119 작성 화면 — 정차가 확실할 때만, G5). 정지가 실려 온 스냅숏(넘겨받음 · 저장 복원)의 첫 반대 입력도 5초 디바운스.
- **「워치 신호 없음」 안내 다시 내기**(2026-11-08) — 응답 뒤(S1R · S2)에 안내를 낸 채 S0 으로 돌아가고 워치가 여전히 낡았으면 S0 에서 안내를 다시 낸다.
- **테스트 모드** — 모든 지시 · 문자에 테스트 표시를 싣는다. 보호자 문자 앞에 「[테스트 · 실제 상황 아님]」. 119 작성 화면은 **미리보기만**(보내기 경로를 열지 않음). 코드 수준에서 「119 로 보내는 함수」는 존재하지 않게 한다(반자동 작성 화면만).

## 5. 차 앱(Pleos)

- 차량 상태 — 속도 `PERF_VEHICLE_SPEED`(android.car), 기어 · 주차 브레이크 · 브레이크 페달 · 착석 · 에어백 전개(Vehicle), 차종 `INFO_MAKE` · `INFO_MODEL` · `INFO_MODEL_YEAR`(android.car, 안 되면 등록값), 위치 `getCurrentLocationInfo`(NaviHelper).
- 경보 — Pleos TTS(ON_DEVICE, Prenim `VoiceGuide` 와 같은 방식), 오디오 포커스 `GAIN_TRANSIENT`. 화면은 주행 중 한 줄 · 터치 0, 정지 때만 버튼 하나(G5).
- 졸음쉼터 — 주행 중에는 음성 제안만. 정지 뒤 `requestNavigationScreen(SearchPlace)` 로 내비 검색 화면을 연다. 좌표 자동 안내(공공데이터 졸음쉼터 목록)는 v2.
- 앰비언트 — `setAmbientLightSwitch` · `setAmbientLightBrightnessColor` 어댑터를 두되 **기본 꺼짐**. 사용자 요청(파랑 · 빨강 깜빡임 · 최대 밝기)은 법 조사 결과와 Vehicle Control 승인 뒤 켠다. 에뮬레이터에서 동작만 실측.
- 정차 · 비상등 — 하지 않는다(G6). 음성으로 「비상등 버튼을 누르세요」만.
- 실행 유지 — 감시 중 포그라운드 서비스(Pleos 비내비 앱 기준 [미검증]).

## 6. 휴대폰 앱

- 등록 · 동의 — 이름 · 생년(만 나이 계산) · 차량 색상 · 번호 · **보호자 이름 · 연락처(필수)**, 동의 세 가지(G9: 긴급 연락 정보 · 건강 관련 별도 · 위치 제3자 제공). 기능은 기본 꺼짐(G1).
- 알람 — `USAGE_ALARM`, 알람 음량 최대(끝나면 복원), 반복. 방해 금지 우회는 사용자 허가 화면 안내.
- 보호자 문자 — `SmsManager`(SEND_SMS 런타임 권한). 베타는 직접 설치라 Play 심사와 무관, 공개 배포 때 Play 예외 심사(G4). 장문은 `divideMessage` · 다중 전송.
- 응답 확인 꺼짐 문자(사용자 결정 2026-11-08) — 실제 사건에서 보호자 사건 문자(EVENT 또는 ACCIDENT)를 보낸 뒤 취소 문자 없이 운전자가 휴대폰에서 켬을 끄면, 끄는 순간(서비스가 멈추기 전) 휴대폰 보낸 기록만 보고 「HH:MM에 휴대폰에서 응답 확인이 꺼졌습니다. 이후 운전자 상태는 앱으로 확인되지 않습니다.」 한 통을 사건마다 한 번 보낸다. 동의 철회 · 테스트 사건 · 문자를 보내기 전에는 보내지 않고, 차 · 중계 · 계약은 그대로다.
- 119 — `ACTION_SENDTO`(`smsto:119`, `sms_body`) 반자동, 정지 뒤에만(G4 · G5). 「119 신고」 앱은 패키지 확인 뒤 실행 연결(조사 중).
- 위치 — `LocationManager.getCurrentLocation`(Note10+ Android 12). 역지오코딩은 `Geocoder`.
- 예비 판정 — 차 링크가 끊기면 같은 상태 기계를 휴대폰이 돌린다. 이때 정지 판정은 휴대폰 GPS 속도로 대신한다 [추정].
- 테스트 모드 — 「실신 테스트」 → 워치에 시뮬레이션 시나리오 지시(워치 없으면 휴대폰 단독 시뮬레이션) → 흐름 → 확인 대화 뒤 **보호자 번호로 테스트 문자**.

## 7. 중계 프로토콜(요지 — 상세는 `contracts/guardian/protocol.md`)

| 엔드포인트 | 보내는 쪽 | 요청 | 응답 |
|---|---|---|---|
| `POST /v1/pair/start` | 차 | `{}` | `{pairCode(6자리, 10분), carToken}` |
| `POST /v1/pair/join` | 휴대폰 | `{pairCode}` | `{phoneToken, pairId}` |
| `POST /v1/car/sync` | 차 | `{carToken, seq, vehicle, flow?, acks[]}` | `{phone, commands[], serverTime}` |
| `POST /v1/phone/sync` | 휴대폰 | `{phoneToken, seq, watch, phoneLocation, flow?, commands[], acks[]}` | `{car, commands[], serverTime}` |
| `POST /v1/pair/end` | 둘 다 | `{token}` | `{}` |

- 지시 — `{id, type, payload, ttlMs, test}`. type 은 `ALERT_START` · `ALERT_STOP` · `SPEAK` · `SHOW` · `AMBIENT` · `OPEN_SEARCH` · `TEST_SCENARIO` · `FLOW_SNAPSHOT`.
- 보관 — 메모리만, 짝 24시간, 상태는 최신 1건, 건강 값은 상태 코드 · 심박 정수 · 마지막 맥박 시각만, 로그에 건강 값 · 위치를 남기지 않는다(G2).
- 토큰 — 무작위 128비트. 베타는 LAN 한정 HTTP, 공개는 HTTPS.

## 8. 문자 양식(`:shared` report)

- G9 순서 그대로(위치 맨 앞). 전체 판 마지막 두 줄은 사용자 지시대로 「회신: 이 번호(운전자 휴대폰 번호)」와 「보호자: 이름 · 연락처」(필수 — 지병 확인 수단).
- 동의 조합에 따라 줄을 뺀다 — 건강 관련 동의가 없으면 「워치」 줄 없음, 위치 동의가 없으면 자동 문자 없음(반자동만).
- 짧은 판 · 전체 판, 테스트 접두.
- 받는 사람별 — 보호자 문자는 같은 본문 + 「앱이 보낸 안내」. 119 는 반자동 작성 화면에만 쓴다.

## 9. 법 준수 매핑

| 가이드라인 | 구현 지점 |
|---|---|
| G1 표현 | 모든 문자열을 한 파일(`:shared` 문구 표)에 모으고 금지어 정적 시험 |
| G2 민감정보 | 원신호는 워치 밖으로 안 보냄, 중계 메모리만 · 로그 금지, 차에 건강 값 저장 금지 |
| G3 위치 | 동의 없으면 위치 줄 · 자동 문자 없음, 제공 때마다 운전자 알림 |
| G4 119 | 자동 전화 · 자동 119 문자 코드 없음, 반자동만, 테스트에서는 미리보기만 |
| G5 운전 중 조작 | 주행 중 응답은 워치 · 차 화면 버튼 하나, 휴대폰 조작 화면은 정지 때만 |
| G6 차량 제어 | 정차 · 비상등 코드 없음, 앰비언트 기본 꺼짐 |
| G7 순정 | 문구에 「순정이 세운다」 없음 |
| G9 양식 | `:shared` 양식 함수 + 단위 시험(동의 조합 8가지) |

## 10. 시험

- 단위(JVM) — 관문(합성 신호: 정상 · 급감 · 소실 · 느슨함 · 미착용 · 움직임), 상태 기계 전이표 전부, 타이머, 주인 넘김, 문자 양식(동의 조합 · 테스트 접두 · 글자 수), 프로토콜 직렬화, 금지어.
- 서버 — Python unittest(짝짓기 · sync · 지시 전달 · TTL · 토큰 · 로그에 건강 값 없음).
- 빌드 — 모든 모듈 `assembleDebug`. Sensor SDK 파일이 없으면 `:watch` 는 시뮬레이션 · Health Services 경로로만 빌드되게 한다.
- 에뮬레이터(사용자 승인 뒤) — Pleos 에뮬레이터의 차 앱 + Mac 중계 + 휴대폰(Pixel_8 AVD 또는 Note10+). 차량 속도 · 기어는 가상 콘솔로 바꾼다.
- 실기기 베타(사용자) — Watch9 개발자 모드, Note10+ 설치, 실신 테스트 모드로 보호자 테스트 문자.

## 12. v1.1 보완 (2026-10-30, 조사 R-DEV · R-119 반영)

- **시험 휴대폰 문제.** Galaxy Watch9 는 「Android 13 이상 · RAM 1.5GB 이상」 휴대폰만 짝 가능하다(삼성 US ANS10013273 · MY 호환표, PM 원문 확인). Note10+ 의 마지막 판은 Android 12 라 **Watch9 와 짝이 안 된다.** Watch8 은 Android 12 이상이라 Note10+ 와 짝이 된다. Wear OS 워치는 처음 설정에 휴대폰이 반드시 필요하다(삼성 US ANS10002899). → 사용자 결정 대기(휴대폰 구성).
- **설계 보완 — 워치 직접 경로.** 어느 휴대폰 구성이든 동작하게, 워치가 중계에 직접 붙는 `POST /v1/watch/sync` 와 역할별 짝 참여(`role: PHONE|WATCH`)를 추가했다. 휴대폰 경유(Data Layer)와 직접 중 최신 것을 중계가 고른다. 지시에는 `to: PHONE|CAR|WATCH|ALL` 이 붙는다. 워치 → 인터넷은 짝 휴대폰의 블루투스 경유 또는 Wi-Fi(베타는 같은 Wi-Fi).
- **에뮬레이터 차량 신호.** 속도 · 기어는 가상 콘솔로 바뀐다(실측 기록). 주차 브레이크는 콘솔 항목이 없고 에어백 전개는 에뮬레이터 미지원 → 정지 판정은 「속도 ≤3 + 기어 P」로 시험, S5 는 시뮬레이션 주입.
- **네트워크.** 중계는 `0.0.0.0` 바인딩, 휴대폰 · 워치 debug network security config 에 Mac LAN IP 를 빌드 설정값으로 주입(지금 Prenim 은 10.0.2.2 만 허용).
- **Data Layer.** 워치 · 휴대폰 applicationId 와 서명이 같아야 한다(공식). 같은 Mac 디버그 키로 빌드.
- **Sensor SDK 받기.** 개요 페이지 받기 버튼 「v1.4.1 (70.8 KB)」, 약관 「SAMSUNG HEALTH PARTNER SERVICE & SDK LICENSE AGREEMENT」 동의 방식, 로그인 불요로 보임. 약관 동의 주체는 사용자.
- **119 문자.** 장문 한 통(LMS, 한글 1,000자)으로 보내고 나누지 않는다. 첫 40자 안에 좌표. 초단문 예비(SMS 80byte). 꼬리는 「확인 전화: 이 번호 또는 보호자」. 「119신고」 앱 `com.winitech.mm119t` 도 위치를 넣은 MMS · SMS 를 보내는 방식(소방청 Play 설명) → `<queries>` + `getLaunchIntentForPackage`, 없으면 스토어.

## 13. v1.2 보완 (2026-10-30, 조사 R-CAR 반영)

- **앰비언트.** Pleos API 는 좌석 구역별 ARGB 색 · 정수 밝기 · 켬/끔만 있고 깜빡임 기능이 없다(Vehicle 2.3.2 `Light.kt:841 · 887 · 932`, PM 확인). 깜빡이려면 앱이 반복 호출해야 하고 응답 속도 · 호출 제한은 [미검증]. 쓰기 권한은 인터페이스 표기 CAR_LIGHTS · 구현 표기 CONTROL_CAR_LIGHTS 로 엇갈린다.
- **법.** 파랑 · 빨강 교대 점멸 · 최대 밝기는 자동차규칙 제47 · 58조, 도로교통법 제42 · 49조와 충돌할 수 있어(PM 원문 확인 — 제58조 경광등은 긴급자동차만, 제47조 앞면 적색 · 점멸 등화 제한) G6 에서 막았다.
- **구현.** `:car` 앰비언트 어댑터는 모드 세 가지 — `INTERIOR_ALERT`(호박색 한 번, 깜빡임 없음), `PARKED_RESCUE`(정차 뒤 백색 · 최대 밝기 조회값), `BLUE_RED_BLINK`(사용자 요청, **법률 검토 전 실행 불가 — 코드 상수로 막음**). 모두 Vehicle Control 승인 전에는 꺼짐, 에뮬레이터 실측만.

## 14. v1.3 상태 기계 보완 (2026-10-30, be-qa :shared 1차 반영 · PM 결정)

- **사건 타이머는 응답만 멈춘다.** S1 에서 응답 없이 정지하면 S2 가 아니라 **AP** 로 가고, 첫 경보부터 이어서 35초가 되면 S4. 워치 신호가 끊기거나 판정이 정상으로 돌아와도 무응답 타이머는 계속 간다. S2 는 「응답한 뒤 정차 관찰」 전용.
- **한 사건 안에서 타이머 연속.** S1 ↔ AP 전환에도 첫 경보 시각 · 단계를 이어 간다. 정지 · 주행 판정은 디바운스 5초, 속도 null 한 번은 직전 판정 유지.
- **S4 에서 차가 움직이면 S3.** 정차 화면 · 백색 조명을 거두고 실내 호박색, 주행 중 119 작성 지시 없음. 차량 입력을 타이머보다 먼저 반영하고, S4 진입 직전에 정지를 다시 확인.
- **취소 뒤 다시 나빠지면 새 사건.** 새 eventId, 사건 문자 1회 + 취소 1회는 사건마다.
- **응답 뒤 휴지(S1R) 중에도** 맥박 신호 약해짐이 30초 이어지면 재경보(잡히지 않음은 즉시).
- **ALERT_START durationMs 는 단계 표시용**, 경보는 ALERT_STOP 까지 계속.
- **첫 40자 좌표 규칙**은 119 · 보호자 · 테스트 판 모두. 테스트 접두는 `[테스트]`(둘째 줄에 「실제 상황 아님」), 보호자 첫 줄은 `[앱 안내] {좌표} 운전자 응답 없음`.
